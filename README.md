# KvK Team Builder

KvK参加者一覧を解析し、参加時間に応じたA〜Kの配置と交代を
Google OR-Tools CP-SATで自動生成するPython CLIです。

## 主な保証

- 集結主、代理集結主、役割、人数をJSONマスタで管理
- 21:00〜25:00を30分単位で最適化
- 各時間帯で確定参加者の重複0・未配置0
- A〜Cは8人固定かつ全員VC可能
- D〜Kは最大9人、8人未満は警告
- 全時間帯で開始戦力を `A > B >= C` に設定
- 9人目とチーム移動を必要最小限に抑制
- 開始時刻が未定のメンバーを待機枠へ分離
- ValidatorがOKを返した結果だけをMarkdown出力

同盟分散は評価しません。同盟が不明な参加者は`未設定`として入力できます。

上記は現在の実装の動作です。実際の運用ルール（所属固定、リーダー数で決まる隊の数、◆やT11の配置、
総力モード、チャット共有用テキストの出力）は
[KvKチーム編成 要件定義書](docs/requirements/team-building/README.md)を目標仕様とし、
順に実装へ反映します（ADR 0023）。

## 必要環境

- Python 3.11以上

Windowsでの開発には、Docker DesktopとVS CodeのDev Containersを推奨します。Docker Desktopの
WSL 2バックエンドだけで利用でき、Ubuntuなどの利用者向けWSLディストリビューションは必須では
ありません。手順は[開発ガイド](DEVELOPMENT.md)を参照してください。

```bash
python -m pip install -e ".[dev]"
```

## 使い方

```bash
python -m kvk_team.interfaces.cli sample/参加者一覧.md チーム編成.md
```

パッケージのスクリプトがPATHに含まれている場合は、次でも実行できます。

```bash
kvk-team-builder sample/参加者一覧.md チーム編成.md
```

同梱のチームマスタと`sample/`の名前、役割、運用メモは架空の例です。実際の運用では、本物の集結主、
代理集結主、役割、運用メモを書いたチームマスタを`--team-master`で指定します。本物のチームマスタ、
参加者一覧、出力は、Git管理外の`tmp/`へ置き、コミットしません。

```bash
python -m kvk_team.interfaces.cli tmp/参加者一覧.md tmp/チーム編成.md --team-master tmp/team_master.json
```

指定したファイルを読み込めない場合は、パスと理由を表示して終了コード2で終わり、出力を書きません。
`--team-master`を省略すると、同梱の例で編成したことを標準エラーへ注意として表示します。
イベントの前に一度`--team-master`付きで実行し、読み込みエラーがないことを確かめてください。

## 入力形式

同盟名とTierを指定した後に参加者を記述します。参加者は1行ずつ、または
読点・カンマ区切りでTierと同じ行に記述できます。

```markdown
同盟名:SKY

G8:山田◯◇、いろは◯◇
G7:ぽてと◯◇△（〜2330頃）

途中から参加
G5:Alice◇（22-24）、Bob [VC]（23時〜）
```

| 記法 | 意味 |
|---|---|
| `◯` / `○` / `〇` | マンスリー持ち（戦力補正なし） |
| `◇` / `[VC]` | VC可能 |
| `△` | 途中抜け |
| `最後まで` | イベント終了まで参加 |
| `25時まで` | 25:00まで参加 |
| `24時まで` | 24:00まで参加 |
| `23時まで` | 23:00まで参加 |
| `22-24` | 22:00から24:00まで参加 |
| `21時半〜22時半` | 21:30から22:30まで参加 |
| `途中参加` / `[途中参加]` | 21:00より後から参加 |
| `時間未定` | 今回の待機枠として分離 |

時間指定がない参加者は「21:00から25:00まで」を既定値とします。
`遅れるかも`は完全な時間未定とは区別し、今回の確定参加者として扱います。

Tierは`G8`、`G7`、`G6`、`G5`に対応します。`G4以下`、`G4`、`G3`、
`その他`はその他Tierとして扱います。

## JSONチームマスタ

チームの運用ルールは
[team_master.json](src/kvk_team/team_building/adapters/persistence/team_master.json)で管理します。Pythonコードに
集結主を埋め込んでいないため、コード変更なしで設定を更新できます。同梱のファイルは公開用の例で、
集結主、代理集結主、役割、運用メモは架空です。本物を書いたファイルはコミットせず、同じ形式でGit管理外に
置いて`--team-master`で指定します（ADR 0026）。同梱のファイルでそれ以外の設定（イベント時間、人数、
VC、戦力関係）が変わったときは、本物のファイルへも同じ変更を反映してください。本物のファイルは
自動では更新されず、古い値のまま読み込まれます。

主な設定項目は次のとおりです。

| 項目 | 内容 |
|---|---|
| `event` | 開始、終了、時間刻み |
| `rally_leader` | 固定集結主 |
| `substitute_leaders` | 固定集結主が不在時の代理 |
| `role` | チームの役割の表示名（同梱の例は`役割A`などの仮の名前） |
| `minimum_members` | 目標人数 |
| `maximum_members` | 同時配置の上限 |
| `vc_required` | 全員VCを必須とするか |
| `notes` | 運用メモ |
| `strength_relations` | 全時間帯で維持する戦力関係 |

同梱の例の集結主（架空の名前）は次のとおりです。

| チーム | 集結主 | チーム | 集結主 |
|---|---|---|---|
| A | 山田 | G | ハルカ |
| B | さくら | H | mt |
| C | taro | I | もも |
| D | わんこ | J | ミカン |
| E | もーもー | K | 翡翠 |
| F | いろは |  |  |

マスタの読み込みは`TeamMasterRepository`に依存します。現在は
`JsonTeamMasterRepository`を使用し、将来はサービス層を変更せずDB実装へ
差し替えられます。

| Tier | 戦力 |
|---|---:|
| G8 | 400 |
| G7 | 300 |
| G6 | 200 |
| G5 | 100 |
| その他 | 20 |

マンスリー補正は適用しません。

## 動的編成

開始・終了時刻が確定したメンバーは、参加可能な各30分スロットへ必ず1チームだけ
配置されます。途中参加者や途中離脱者は、前後のメンバーとの差分として交代表へ
出力されます。

開始時刻が未定のメンバーは人数、戦力、VC保証へ算入せず、`時間確定待ち`へ
出力します。到着時刻が確定した時点で再実行してください。固定集結主が未定の場合は、
参加中の代理集結主を使用し、代理も不在なら警告を出します。

チーム役割は現時点では表示情報です。将来メンバー属性が追加された場合、
役割適性を制約または目的関数として拡張できます。

## 出力

- チームごとの21:00初期配置
- 時刻別の退出・参加差分
- 時間確定待ちメンバー
- 30分ごとの人数、戦力、VC人数、集結主
- 必須条件の自己チェック
- 人数不足や集結主到着待ちの警告

警告は必須条件違反ではありません。特に24:00以降など、参加者総数が少なく
D〜Kを8人にできない時間帯は不足人数を明示します。

## 出力できない場合

必須条件を満たす編成を出力できない場合は、ファイルを書かずに終了コード2で終了し、
原因を区別した`エラー:`を表示します。

| 表示 | 意味 | 対処 |
|---|---|---|
| `…編成は存在しません` | 必須条件を満たす編成が存在しないと確定した | 参加者、VC、参加時間、チーム人数を見直す |
| `…見つかりませんでした。時間切れのため…` | 制限時間（既定30秒）内に解が見つからず、存在の有無は未確定 | 負荷の低い環境で再実行する |
| `…VC参加者が不足しています` | 最適化の前に、A〜Cへ必要なVC人数が足りないと判明した | VC可能な参加者を増やすか参加時間を見直す |

## 開発

```bash
python -m pip install -e ".[dev]"
python tools/check.py
```

品質ゲートはWindowsとLinux、Python 3.11と3.12で共通です。Ruffによる
フォーマット・Lint、mypyによる型検査、pytestを順に実行します。開発方針と詳しい
セットアップは[開発ルール](AGENTS.md)と[開発ガイド](DEVELOPMENT.md)を参照してください。

設計は「KvKチーム編成」をコアドメインとする戦術的DDDを段階導入します。用語、境界、
パッケージ構造は[ドメインモデル](docs/domain-model.md)を参照してください。
Webアプリ化に向けて、`src/kvk_team/`の下へ「KvKチーム編成」と「戦闘タイミング」の
2つのコンテキストを置き、`frontend/`にReactのFEを置く構成へ移行します（ADR 0021）。
「KvKチーム編成」は`src/kvk_team/team_building/`へ移行済みです。

CodexまたはClaude Codeで変更をレビューする場合は`$review-kvk-change`、編成ルールを
変更する場合は`$change-kvk-rules`、Web UIを設計・実装・レビューする場合は`$apple-design`を
使用できます。Claude Codeでは`$`を`/`に読み替えます（例: `/review-kvk-change`）。

```text
src/kvk_team/
  team_building/
    domain/       参加者、チーム、時間帯別編成、チームマスタ、編成ルール、参加時間、独立検証
    application/  編成パイプラインと境界（ports）
    adapters/
      input/          Markdown入力解析
      optimization/   時間帯別CP-SAT
      output/         初期配置・交代表・集計のMarkdown出力
      persistence/    JSONチームマスタとRepository
  interfaces/
    cli/          CLIと既定部品の組み立て
tests/          pytestテスト
sample/         実行可能な参加者一覧
docs/           設計文書、ブラウザ用補助ツールの要件定義書
web/            独立したブラウザ用補助ツール（Python処理の対象外）
.github/        CI設定
```

詳しくは[アーキテクチャ](docs/architecture.md)を参照してください。

### ブラウザ用補助ツール（web/）

`web/`には、KvK当日に使う単体HTMLツール（攻城タイムライン計算、占領判定、同着カウント、
周期ウェーブタイマー）を置いています。これらは編成CLIとは独立しており、計算ロジックの正本は
各HTMLです。PythonのParser、Optimizer、Validator、Exporterへは移植せず、品質ゲートの
対象にも含めません。詳細は[ADR 0013](docs/adr/0013-separate-web-tools-from-python-scope.md)を
参照してください。

各ツールの機能、入出力、計算規則、既知の不具合は
[ブラウザ用補助ツール 要件定義書](docs/requirements/web-tools/README.md)で管理します。
ツールを修正するときは、要件定義書を先に更新します。
