# KvK Team Builder

KvK参加者一覧を解析し、リーダー一覧から作る隊へメンバーの所属を固定して割り当てる編成を
Google OR-Tools CP-SATで自動生成するPython CLIです。

## 主な保証

- 隊の数はリーダーの人数とし、リーダー一覧の順を隊の番号（第1隊、第2隊…）にする
- リーダー一覧はイベントごとの`settings.json`、戦闘時間と上限はJSONチームマスタで管理
- 所属は時間帯をまたいで変わらず、各時間帯は所属メンバーのうち参加中の人と、応援に来た人が出撃する
- 21:00〜25:00を30分単位で検証
- 参加時間が確定した参加者は、ちょうど1つの隊に所属するか待機になる
- 第1〜3隊はリーダーを含めて8人固定かつ全員VC可能。リーダー不在の時間帯は7人で警告
- 第4隊以降は最大9人、8人未満は警告
- 全時間帯で戦力を `第1隊 > 第2隊 >= 第3隊` に設定
- 24:00より前に所属メンバーが0人になる隊（休止）があれば、番号付きの質問を示して出力しない。序盤の休止には、
  回答のファイルで遅れて出撃させる隊と応援先を答えられる
- 開始時刻が未定のメンバー（リーダーを含む）を【別枠】参加時間未定へ分離
- ValidatorがOKを返した結果だけを出力する。出力のフォルダの`<実行の時刻>/`へ、編成のMarkdownと編成のJSONを
  上書きせずに書く。共有した回の編成のJSONは、次の実行へ前回の編成（`--previous`）として渡せる

同盟分散は評価しません。同盟が不明な参加者は`未設定`として入力できます。

上記は現在の実装の動作です。実際の運用ルール（下限に満たない場合の選択肢の提示、
◆やT11の配置、総力モード、チャット共有用テキストの出力）は
[KvKチーム編成 要件定義書](docs/requirements/team-building/README.md)を目標仕様とし、
順に実装へ反映します（ADR 0023）。

## 必要環境

- Python 3.11以上

Windowsでの開発には、Docker DesktopとVS CodeのDev Containersを推奨します。Docker Desktopの
WSL 2バックエンドだけで利用でき、Ubuntuなどの利用者向けWSLディストリビューションは必須では
ありません。手順は[開発ガイド](DEVELOPMENT.md)を参照してください。

運用では`main`（リリース済みの版）を使ってください。`dev`は次のリリースへ向けて統合中の版です
（ADR 0027）。新しく複製する場合は`git clone -b main <RepositoryのURL>`、複製済みの場合は
`git switch main`の後に`git pull`で最新のリリースへそろえてから、インストールします。

```bash
python -m pip install -e ".[dev]"
```

## 使い方

```bash
python -m kvk_team.interfaces.cli sample/参加者一覧.md tmp/preview/output
```

パッケージのスクリプトがPATHに含まれている場合は、次でも実行できます。

```bash
kvk-team-builder sample/参加者一覧.md tmp/preview/output
```

2つ目の引数は出力のフォルダです。実行するたびに`<出力のフォルダ>/<実行の時刻>/`（例:
`tmp/preview/output/20260101-205230/`）を作り、編成のMarkdown（`チーム編成.md`）と編成のJSON
（`チーム編成.json`）を書きます。時刻は実行した計算機の現地時刻で、同じ時刻のフォルダがあれば`-2`、`-3`を
付けて、前の出力を上書きしません（DAT-008、ADR 0036）。作ったフォルダは標準出力に表示します。以前の版のように
`チーム編成.md`などの`.md`で終わるパスを渡すと、置き方が変わったことを示して終了コード2で終わります。

同梱のリーダー一覧の例と`sample/`の名前は架空です。実際の運用では、本物のリーダー一覧を書いた
`settings.json`を`--settings`で指定します。本物の`settings.json`、参加者一覧、出力は個人名を含むため、
メインの作業ツリーのGit管理外の`tmp/events/<開催日>-<イベント名>/`などへ置き、コミットしません
（DAT-001、ADR 0029）。

```bash
python -m kvk_team.interfaces.cli tmp/events/2026-01-01-example/参加者一覧.md tmp/events/2026-01-01-example/output --settings tmp/events/2026-01-01-example/settings.json
```

指定したファイルを読み込めない場合は、パスと理由を表示して終了コード2で終わり、出力を書きません。
`--settings`を省略すると、同梱の例（架空のリーダー一覧）で編成したことを標準エラーへ注意として表示します。
イベントの前に一度`--settings`付きで実行し、読み込みエラーがないことを確かめてください。
戦闘時間や上限を変える場合は、チームマスタを`--team-master`で指定します。

24:00より前に休止になる隊があると、番号付きの質問を標準エラーへ表示し、出力を書かずに終了コード3で
終わります（[出力できない場合](#出力できない場合)）。序盤（戦闘開始からの1時間）の問いには、遅れて出撃させる隊と
応援先を`answers.json`に書き、`--answers`で渡して再実行します。回答も個人名を含むため、イベントのフォルダに置きます。

```bash
python -m kvk_team.interfaces.cli tmp/events/2026-01-01-example/参加者一覧.md tmp/events/2026-01-01-example/output --settings tmp/events/2026-01-01-example/settings.json --answers tmp/events/2026-01-01-example/answers.json
```

共有した回のフォルダの`チーム編成.json`を`--previous`で渡すと、前回の編成として読み込みます。この版では
読み込みと今回の参加者一覧との照合だけに使い、編成には使いません（前回からの移動の数（FRM-071）は今後の版で
比べます）。そのことを標準エラーへ注意として表示し、編成を出力したときは、前回の編成にいて今回の参加者一覧
（名前と同盟の組）にいない人がいれば、その人数だけを名前なしで表示します（番号付きの質問で止まった実行では表示しません）。いない人がいてもエラーにはしません。

```bash
python -m kvk_team.interfaces.cli tmp/events/2026-01-01-example/参加者一覧.md tmp/events/2026-01-01-example/output --settings tmp/events/2026-01-01-example/settings.json --previous tmp/events/2026-01-01-example/output/20260101-205230/チーム編成.json
```

| 終了コード | 意味 |
|---|---|
| 0 | 編成を出力した |
| 2 | 入力のエラー（ファイル、出力のフォルダ、参加者一覧、チームマスタ、`settings.json`、`answers.json`、前回の編成のJSON）か、必須条件を満たす編成がないと確定した |
| 3 | 運用者の回答が要る。番号付きの質問を表示し、出力を書かない |
| 4 | 時間切れ。制限時間内に結果を確定できなかった。負荷の低い環境で再実行する |

## 回答の書き方

回答には質問の番号ではなく、問いの対象（`target`）と指定そのもの（`late_start`）を書きます。質問の文に
回答の対象が表示されます。1つの問いが同じ隊の複数の時刻をまとめている場合は、直したい時刻を1つ書きます。
書いた時刻の休止がなくなる回答だけを受け入れ、残りの時刻は次の実行で改めて問われます。応援は、遅れて出撃させる隊の所属にするメンバーが出撃開始前に
参加する時間帯ごとに、応援先の隊を書きます。次の例は戦闘開始が21:00の回で、第7隊の21:00の問いに、第10隊を
22:00から出撃させ、第10隊に所属するカイが21:00と21:30に第7隊を応援すると答えたものです。応援は休止の判定に
数えず、休止中の隊は応援先にならないため、応援だけで休止は直りません。休止した隊自身を遅らせる回答が基本です。

```json
{
  "answers": [
    {
      "target": {"team": 7, "time": "21:00"},
      "late_start": {
        "team": 10,
        "start": "22:00",
        "support": [
          {"member": {"name": "カイ", "alliance": "AAA"}, "time": "21:00", "team": 7},
          {"member": {"name": "カイ", "alliance": "AAA"}, "time": "21:30", "team": 7}
        ]
      }
    }
  ]
}
```

- 遅れて出撃させられるのは第4隊以降、応援先は第5隊以降のほかの隊です（FRM-041、FRM-042）
- 出撃開始時刻は戦闘開始より後の30分の区切りです。出撃開始前に参加するメンバー（リーダーを含む）には、
  参加する時間帯すべてに応援先が要ります。応援するメンバーは、その遅れて出撃する隊に所属します
- アプリは回答を覚えません。次の質問への回答は、同じファイルへ足して再実行します。回答の順は結果に影響しません
- ほかの指定によらず誤っている回答（ない隊やメンバー、第1〜3隊を遅らせる、序盤以外の問いへの回答など）は、
  名前を書かずに、回答の対象と応援の時刻と応援先を示して終了コード2で終わります
- 対象が下限を満たした回答は使わず、成り立たない回答は受け入れず、それぞれ理由を「注記:」に示します
- 序盤以外の休止の問いには、この版では回答できません（回答を書くと終了コード2）。隊数を減らす、明示して許すの
  選択肢は今後の版で加えます

形式の詳細は要件定義書のDAT-009、確かめる手順は作成者の仮定A-41とADR 0035を参照してください。

## 入力形式

同盟名とTierを指定した後に参加者を記述します。参加者は1行ずつ、または
読点・カンマ区切りでTierと同じ行に記述できます。

```markdown
同盟名:SKY

G8:山田◯◇、いろは◯◇
G7:ぽてと◯◇△（〜2330頃）

途中から参加
G5:Alice◇（22-24）、Bob [VC]（23時〜）
```

| 記法 | 意味 |
|---|---|
| `◯` / `○` / `〇` | マンスリー持ち（戦力補正なし） |
| `◇` / `[VC]` | VC可能 |
| `△` | 途中抜け |
| `最後まで` | イベント終了まで参加 |
| `25時まで` | 25:00まで参加 |
| `24時まで` | 24:00まで参加 |
| `23時まで` | 23:00まで参加 |
| `22-24` | 22:00から24:00まで参加 |
| `21時半〜22時半` | 21:30から22:30まで参加 |
| `途中参加` / `[途中参加]` | 21:00より後から参加 |
| `時間未定` | 【別枠】参加時間未定として分離 |

時間指定がない参加者は「21:00から25:00まで」を既定値とします。
`遅れるかも`は完全な時間未定とは区別し、今回の確定参加者として扱います。

Tierは`G8`、`G7`、`G6`、`G5`に対応します。`G4以下`、`G4`、`G3`、
`その他`はその他Tierとして扱います。

## チームマスタと運用者の指定

設定は、Repositoryで管理する常設の既定値（チームマスタ）と、イベントごとに運用者が渡す指定
（`settings.json`）に分けます（ADR 0034）。上位隊の3隊×8人、出撃人数の下限の基本8人、延長境界時刻の24:00、30分単位の時間帯は
利用者が決めた固定値で、設定では変えません。

[team_master.json](src/kvk_team/team_building/adapters/persistence/team_master.json)は名前を含まず、
次の項目だけを持ちます。

| 項目 | 内容 |
|---|---|
| `schema_version` | `2`。隊ごとの集結主を持つ以前の形（`1`）は、移し方を示して読み込みエラーにします |
| `event` | 戦闘の開始（`start_time`）と終了（`end_time`）。開始は30分の区切り（例: 21:00、21:30）とし、長さは30分で割り切れるようにします。時間帯が24:00をまたがないようにするためで、違えば読み込みエラーです。時間刻みは書きません |
| `member_cap` | 第4隊以降の出撃人数の上限（8以上） |

`settings.json`は、要件定義書の[データ形式](docs/requirements/team-building/data-formats.md)のDAT-007に従います。
現在は`leaders`（リーダー一覧）だけを読みます。リーダーは参加者一覧の名前と同盟の組で書き、
並び順が隊の番号になります。リーダーが参加者一覧で1人に決まらない場合は入力のエラーです。DAT-007の
ほかのキー（`pin_team`、`groups`など）は後の実装で読むため、今は黙って無視せず、キーを示して
読み込みエラーにします。

```json
{
  "leaders": [
    {"name": "山田", "alliance": "SKY"},
    {"name": "さくら", "alliance": "FOX"},
    {"name": "taro", "alliance": "SUN"}
  ]
}
```

同梱の例
[settings.example.json](src/kvk_team/team_building/adapters/persistence/settings.example.json)は、
`sample/`の参加者一覧の架空のリーダー11人（山田、さくら、taro、わんこ、もーもー、いろは、ハルカ、mt、
もも、ミカン、翡翠）です。

読み込みは`TeamMasterRepository`と`OperatorSpecificationRepository`に依存し、JSONの実装は
Repository境界に置きます。

## 所属固定の編成

開始・終了時刻が確定したメンバーは、1つの隊に所属するか、上限のため待機になります。所属は
時間帯をまたいで変わらず、各時間帯には所属メンバーのうちその時間帯全体に参加している人が出撃します。
第1〜3隊の所属メンバーは全時間帯に参加するVC可能な人に限られ（例外はリーダーだけ）、
第4隊以降は途中参加や途中離脱の人も所属できます。

リーダーは自分の隊に所属します。リーダーが遅れる時間帯や抜けた時間帯は、代理を決めずに
リーダー不在として出力します（FRM-002、FRM-003）。不在の時間帯には警告を出します（第1〜3隊はFRM-029、
第4隊以降は作成者の仮定A-38）。開始時刻が未定のメンバーは人数、
戦力、VC保証へ算入せず、【別枠】参加時間未定へ出力します。開始時刻が未定のリーダーも別枠に置き、
その隊は全時間帯をリーダー不在とします。到着時刻が確定した時点で再実行してください。

回答で遅れて出撃させた隊は、出撃開始前の時間帯に出撃せず、その時間帯を人数不足や休止として扱いません。
出撃開始前に参加する所属メンバーは、回答の応援先の隊で出撃し、応援先の出撃人数、戦力、VC、上限に数えます。
応援先は、その時間帯に所属メンバーが参加している（休止中でない）隊に限ります（FRM-041、FRM-042、FRM-048）。

隊の人数は、24:00より前の休止をなくすこと、8人に足りない人数を隊の間で均すこと、待機を減らすこと、
第1〜3隊の戦力を高めることの順に決めます。目的関数の優先順位は要件定義書のFRM-037で置き換える予定です。

## 出力

- 隊ごとのリーダーと所属メンバー（VC可能に◇、全時間参加でない人に参加時間）。遅れて出撃する隊には出撃開始時刻
- 応援（時刻、メンバー、所属、「応援→第○隊」）。応援がある場合だけ
- 待機と【別枠】参加時間未定のメンバー
- 時間帯ごとの出撃人数（応援を受けた時間帯は応援の人数を添える）、戦力、VC人数、リーダー。出撃開始前の時間帯は
  「出撃開始前」
- 回答の扱いの注記（使わなかった回答、受け入れなかった回答）。注記がある場合だけ
- 必須条件の自己チェック
- 人数不足とリーダー不在の警告

上はMarkdown（`チーム編成.md`）の内容です。同じフォルダの編成のJSON（`チーム編成.json`）は、次の実行の前回の編成
として読むためのもので、版（`schema_version`）、時差付きの実行の時刻（`created_at`。フォルダ名と同じ時刻）、隊ごとの番号、リーダー、
出撃開始時刻、所属メンバーと、応援、待機、別枠を、メンバーを`{"name": 名前, "alliance": 同盟}`で指して持ちます。
形は要件定義書のDAT-010を参照してください。

警告は必須条件違反ではありません。特に24:00以降など、参加者総数が少なく
第4隊以降を8人にできない時間帯は不足人数を明示します。

## 出力できない場合

必須条件を満たす編成を出力できない場合は、出力のフォルダに何も書かずに終了し、原因を区別して表示します。
終了コードは、入力のエラーと解なしが2、運用者の回答が要る場合が3、時間切れが4です。

| 表示 | 終了コード | 意味 | 対処 |
|---|---|---|---|
| `…編成は存在しません` | 2 | 必須条件を満たす編成が存在しないと確定した | 参加者、VC、参加時間、リーダー一覧を見直す |
| `…見つかりませんでした。時間切れのため…` | 4 | 制限時間（既定30秒）内に解が見つからず、存在の有無は未確定 | 負荷の低い環境で再実行する |
| `…全時間帯に参加しVC可能なメンバーが不足しています` | 2 | 最適化の前に、第1〜3隊へ必要な人数が足りないと判明した | VC可能な参加者を増やすか参加時間を見直す |
| `…のリーダー…がVC不可のため…` | 2 | 第1〜3隊のリーダーがVC不可 | リーダー一覧の順か参加者一覧を見直す |
| `運用者の判断が要るため、編成を出力しません。`と`問1: …` | 3 | 最適な編成でも、24:00より前に所属メンバーが0人になる隊が残る。隊と、序盤かどうかでまとめた問いに番号を付けて示し、回答の扱いを`注記:`に示す | 序盤の問いには遅れて出撃させる隊と応援先を`answers.json`に書いて再実行する。序盤以外の問いには、この版では回答できないため、参加者一覧かリーダー一覧を見直す |
| `…休止が避けられないかを確定できません。時間切れのため…` | 4 | 最適だと示せないまま休止が残り、避けられるかは未確定 | 負荷の低い環境で再実行する |
| `リーダー一覧のN番目…が、名前と同盟の組で参加者一覧に見つかりません` / `…2人以上に当たります` | 2 | リーダー一覧のメンバーが参加者一覧で1人に決まらない。個人名がエラーから漏れないよう、名前ではなく位置で示す | `settings.json`の名前と同盟を参加者一覧に合わせる |
| `第N隊 HH:MMへの回答（…）: …` | 2 | 回答が、ほかの指定によらず誤っている（ない隊、時刻、メンバー、第1〜3隊を遅らせる、序盤以外の問いへの回答、応援先の欠けなど） | `answers.json`を直す |
| `前回の編成を読み込めません: …` | 2 | `--previous`のJSONの形が誤っている（未知の項目、型、版、同じメンバーが2回、同じ番号の隊など）。名前は書かず、位置と項目で示す | 共有した回のフォルダの`チーム編成.json`を、書き換えずに渡す |
| `出力先には出力のフォルダを指定してください` | 2 | 2つ目の引数に以前の版の`.md`で終わるパスを渡した（以前の版の出力のファイルが残っていても、この表示になる） | 出力のフォルダ（例: `<イベントのフォルダ>/output`）を渡す |
| `出力のフォルダがフォルダではありません` / `出力のフォルダを確かめられません` | 2 | 2つ目の引数が既にある（`.md`以外の）ファイルを指すか、親のフォルダを辿れない。編成の前に止める | 出力のフォルダを渡す |

既定の探索は並列で実時間を上限にするため、休止を隊の間で入れ替えられる入力では、問いの対象の隊が実行ごとに
変わることがあります。前の実行の問いへの回答が「使いませんでした」の注記になった場合は、表示された問いに
答え直してください（再現性は要件定義書のFRM-038で扱う予定です）。

## 開発

```bash
python -m pip install -e ".[dev]"
python tools/check.py
```

品質ゲートはWindowsとLinux、Python 3.11と3.12で共通です。Ruffによる
フォーマット・Lint、mypyによる型検査、pytestを順に実行します。開発方針と詳しい
セットアップは[開発ルール](AGENTS.md)と[開発ガイド](DEVELOPMENT.md)を参照してください。

設計は「KvKチーム編成」をコアドメインとする戦術的DDDを段階導入します。用語、境界、
パッケージ構造は[ドメインモデル](docs/domain-model.md)を参照してください。
Webアプリ化に向けて、`src/kvk_team/`の下へ「KvKチーム編成」と「戦闘タイミング」の
2つのコンテキストを置き、`frontend/`にReactのFEを置く構成へ移行します（ADR 0021）。
「KvKチーム編成」は`src/kvk_team/team_building/`へ移行済みです。

CodexまたはClaude Codeで変更をレビューする場合は`$review-kvk-change`、編成ルールを
変更する場合は`$change-kvk-rules`、Web UIを設計・実装・レビューする場合は`$apple-design`を
使用できます。Claude Codeでは`$`を`/`に読み替えます（例: `/review-kvk-change`）。

```text
src/kvk_team/
  team_building/
    domain/       参加者、隊と固定値、運用者の指定、所属固定の編成、編成の記録、チームマスタ、編成ルール、参加時間、独立検証
    application/  編成パイプラインと境界（ports）、Optimizerの結果の型
    adapters/
      input/          Markdown入力解析
      optimization/   所属固定のCP-SAT
      output/         隊、出撃、待機、別枠、自己チェックのMarkdown出力
      persistence/    JSONチームマスタ、運用者の指定（settings.json）、回答、編成のJSONとRepository
  interfaces/
    cli/          CLI、既定部品の組み立て、実行の時刻のフォルダへの出力
tests/          pytestテスト
sample/         実行可能な参加者一覧
docs/           設計文書、ブラウザ用補助ツールの要件定義書
web/            独立したブラウザ用補助ツール（Python処理の対象外）
.github/        CI設定
```

詳しくは[アーキテクチャ](docs/architecture.md)を参照してください。

### ブラウザ用補助ツール（web/）

`web/`には、KvK当日に使うHTMLツール（攻城タイムライン計算、占領判定、同着カウント、
周期ウェーブタイマー）を置いています。これらは編成CLIとは独立しており、計算ロジックの正本は
各HTMLです。PythonのParser、Optimizer、Validator、Exporterへは移植せず、Ruff、mypy、pytestの
対象にも含めません。詳細は[ADR 0013](docs/adr/0013-separate-web-tools-from-python-scope.md)を
参照してください。集結タイムライン計算と周期ウェーブタイマーは、実物のHTMLをNode.jsとjsdomで
動かす`tests/web/`の検査を品質ゲートで実行します。カウントダウン表は、集結タイムライン計算と共有する速度ペットの
ボーナスだけを同じ方法で確かめます（[ADR 0030](docs/adr/0030-test-web-tools-with-node-and-jsdom.md)）。

集結タイムライン計算、周期ウェーブタイマー、カウントダウン表は、許可を得た取り込み元の版へ置き換え、
外部サーバーとの連携を外しています（[ADR 0031](docs/adr/0031-import-upstream-web-tools.md)）。集結タイムライン計算で
計算すると、周期ウェーブタイマーが周期、MAX、タイムラインを自動で受け取ります。

各ツールの機能、入出力、計算規則、既知の不具合は
[ブラウザ用補助ツール 要件定義書](docs/requirements/web-tools/README.md)で管理します。
ツールを修正するときは、要件定義書を先に更新します。
