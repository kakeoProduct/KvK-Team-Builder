# ADR 0006: 変更セッションの共有記憶と知識昇格

- 状態: 採用
- 日付: 2026-07-20

## 背景

CodexのSessionが変わると、以前の実装で得た判断、失敗、検証結果、未完了事項を毎回Codeと
会話から再構築する必要がある。Local Memoryは有用だが、利用者ごとの生成状態であり、非同期、
補助的で、人間を含むRepository利用者の共通正本にはできない。

一方、会話全文をGitへ保存すると秘密情報と個人情報の混入、Repository肥大化、古い判断の
誤適用が起きやすい。変更のない相談や読み取り専用Reviewまで記録すると、重要な引継ぎが
大量の記録へ埋もれる。

さらに、同じ手順や失敗が繰り返されてもSession記録に留まり続けると、毎回検索と再解釈が
必要になる。成熟した知識を`AGENTS.md`、Skill、ADRなどの適切な正本へ移す仕組みが必要である。

## 判断

- 機能実装または有効なRepository変更が発生したSessionだけをGit管理の共有記憶へ記録する
- 利用者が明示した場合は、変更がないSessionも記録できる
- Session開始時のHEADと作業ツリー内容をOSの一時Directoryへ保存し、終了時との差を判定する
- 開始前から存在する利用者差分、共有記憶自身、Git除外対象、一時生成物は変更判定から外す
- `docs/project-memory/sessions/`へSessionごとのMarkdownを追記し、会話全文は保存しない
- `docs/project-memory/candidates/`で昇格候補と複数Sessionの根拠を管理する
- 索引、Schema、参照、明白な秘密情報形式をPython Scriptで決定的に検証する
- 反復した知識は内容に応じて`AGENTS.md`、Skill、Script、正本文書、ADR、Domain Model、
  Review Agent、将来のPluginへ昇格できる
- 昇格候補の検出は自動化できるが、昇格先の変更には利用者の承認または明示的な依頼を必要とする
- 昇格後は昇格先を正本とし、元の記憶は削除せず来歴として残す
- Repository内の共有Workflowを`.agents/skills/maintain-project-memory`へ置く

## 代替案

### CodexのLocal Memoryだけを使う

個人の作業には便利だが、人間、別環境、別利用者と共有できず、必須規約の唯一の保存先には
できないため採用しない。補助的な想起層として併用する。

### 会話全文をGitへ保存する

完全な監査記録になるが、秘密情報、個人情報、長いTool出力、著作物を不用意に永続化する
危険が大きいため採用しない。

### すべてのSessionを記録する

変更のない相談や読み取り専用Reviewが索引を増やし、重要な実装結果を探しにくくするため
採用しない。利用者が明示した場合だけ例外とする。

### DatabaseまたはVector検索を最初から導入する

現在の規模では新しい依存、移行、Backup、検索結果の説明責任が増える。Markdownと生成索引で
十分なため採用せず、記録数と検索時間が実際に問題になった時点で再検討する。

### 条件を満たした候補を自動でSkillへ昇格する

Skillや`AGENTS.md`は将来の全Sessionの振る舞いを変える。誤った一般化や既存責務との重複を
避けるため、候補提示までを自動化し、実昇格は利用者確認後に行う。

## 影響

変更Sessionごとに小さなMarkdownが1件増え、完了前に記憶作成と検証が必要になる。代わりに、
次のSessionは変更理由、検証結果、未完了事項へ短時間で到達できる。個別ファイル方式により
並行Sessionの競合を抑え、WindowsとLinuxで同じPython Commandを利用できる。

共有記憶は正本ではないため、契約や設計判断が変わる場合は従来どおりREADME、Architecture、
ADR、設定、Testを同じ変更で更新する。秘密情報がGitへ入った場合、ファイル削除だけでは履歴から
消えないため、通常の秘密情報IncidentとしてCredential失効と履歴修正を別途判断する。
