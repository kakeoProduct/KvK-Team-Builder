# ADR 0007: 人間の承認判断に向けたレビュー3段階

- 状態: 採用
- 日付: 2026-07-20

## 背景

ADR 0002で採用した`P0`〜`P3`は技術的な重大度を伝えられるが、人間が変更を承認するときに
「修正が必須か」「リスクを受容して見送れるか」「任意改善か」が直接分からない。
複数の専門レビューと統合結果で、承認判断の意味を揃える必要がある。

## 判断

- レビュー指摘を`Must`、`Should`、`Nice`の3段階で報告する
- `Must`は承認前に必ず修正する契約違反または到達可能な失敗とする
- `Should`は原則として承認前に修正し、見送る場合は人間がリスクと追跡方法を受容する
- `Nice`は承認を妨げない任意の改善とし、単なる書式の好みは含めない
- 統合結果の先頭に、`Must`ありは「承認不可」、`Should`ありは「要判断」、それ以外は
  「承認候補」と示す
- ADR 0002の`P0`〜`P3`による報告の判断だけを本ADRで置き換え、読み取り専用、3観点の並列確認、
  根拠と行番号を必須とする方針は維持する

## 代替案

### `P0`〜`P3`を維持する

既存の表記は保てるが、各レベルと承認行動の対応を人間が別途解釈する必要があるため採用しない。

### 影響度と承認判定の2軸を報告する

情報は豊富になるが、指摘の比較と統合が複雑になる。現在のリポジトリ規模では承認行動を優先し、
影響の詳細は各指摘の本文で説明する。

## 影響

レビューの利用者は、統合結果から承認可否と要判断の箇所を直接読み取れる。`Should`を
見送るときは明示的なリスク受容が必要になる。過去のレビュー結果との機械的なレベル比較は
できなくなるが、根拠、失敗経路、最小修正の記載は維持する。
