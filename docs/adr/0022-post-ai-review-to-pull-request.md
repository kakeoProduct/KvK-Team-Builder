# ADR 0022: AIレビュー結果をテンプレートで保存し、Pull Requestへ投稿する

- 状態: 提案中（一部をADR 0024で置き換え）
- 日付: 2026-10-18

## 背景

`$review-kvk-change`は3つの読み取り専用エージェントの結果を統合し、承認判定と`Must`、`Should`、
`Nice`を会話へ報告している（ADR 0002、ADR 0007）。結果は会話の中にしか残らないため、人間が
Pull Request上で承認を判断するときに参照できず、指摘への対応状況も追えない。報告の形式も
Sessionごとに少しずつ異なる。

## 判断

- レビュー結果の形式を`.agents/skills/review-kvk-change/references/review-report-template.md`に
  固定する。承認判定、各レベルの指摘、未確定の懸念、対応状況、実施した検査を必ず含める
- 結果をGit管理外の`tmp/reviews/`へ保存する。Repositoryへはコミットしない
- 対象branchにopenなPull Requestがあれば、`gh pr comment --body-file`でコメントとして投稿する。
  Pull Requestがまだなければ、`$create-github-pr`が作成後に投稿する
- 指摘への対応後は対応状況を更新し、新しいコメントとして投稿し直す。過去のコメントは編集も削除も
  しない
- 投稿はレビュー結果の共有だけとし、GitHubのApprove、Request changes、mergeは行わない。
  承認の判断は人間が行う
- 読み取り専用の原則の例外は、`tmp/reviews/`への保存とコメントの投稿だけとする

## 代替案

### 会話への報告だけを続ける

外部作用は増えないが、Pull Request上で承認を判断する人間が結果を参照できず、対応状況も残らない
ため採用しない。

### レビュー結果をRepositoryの文書としてコミットする

履歴に残るが、変更ごとの一時的な判断が正本の文書へ混ざり、レビューのたびに差分が増えるため
採用しない。

### GitHubのレビュー機能（Approve、Request changes）で投稿する

GitHubの承認状態と連動するが、AIの判定が人間の承認の代わりに見える。指摘の根拠を確かめて承認を
決めるのは人間とする方針（ADR 0007）と合わないため採用しない。

## 影響

レビュー結果と対応状況がPull Requestに残り、承認の判断材料になる。一方、コメントの投稿という
外部作用が加わるため、`gh`の認証がRepositoryへのコメント権限を持つ必要がある（ADR 0008の
スコープ上限の範囲内）。投稿内容は非公開Repositoryの閲覧者全員に見えるため、秘密情報、
個人情報、長いログを含めない。
