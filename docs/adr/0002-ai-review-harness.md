# ADR 0002: AIレビューハーネス

- 状態: 採用
- 日付: 2026-07-19

## 背景

単一の汎用レビューでは、CP-SATのドメイン制約、レイヤー境界、テストの妥当性を同時に
深く確認しづらい。レビューを再現可能にしつつ、エージェントが指摘と修正を混同しない
構成が必要である。

## 判断

- `.codex/agents/`にドメイン、アーキテクチャ、テストの専門レビューエージェントを置く
- すべてのレビューエージェント定義で読み取り専用sandboxと高い推論強度を要求する
- `.agents/skills/review-kvk-change`が3エージェントを並列実行し、主エージェントが結果を
  再検証して統合する
- `.agents/skills/change-kvk-rules`がプロダクトルール変更の分類と実装手順を提供する
- レビュー結果はP0〜P3、正確な行、具体的な発生経路を必須とする
- サブエージェントが使えない環境では、同じ3観点を主エージェントが順に適用する
- 親セッションの実行時権限がTOML設定を上書きし得るため、名前付きエージェント定義または
  読み取り専用sandboxを適用できない環境では汎用エージェントを代用しない

## 代替案

### 1つの汎用レビューエージェント

構成は単純だが、観点が広すぎてプロダクト固有の制約やテスト妥当性が埋もれやすいため
採用しない。

### レビューエージェントにも修正を許可する

複数エージェントの編集競合と、未検証の指摘を即座に実装する危険があるため採用しない。

### セキュリティ専用エージェントを追加する

現状は外部サービスや認証を持たないローカルCLIであり、独立実行の費用に対して対象が
小さい。アーキテクチャレビューへ含め、Web化や外部連携時に分離を再検討する。

## 影響

レビュー時のトークン使用量と待ち時間は増えるが、観点ごとの責任が明確になる。レビュー
は設定と指示の両方で編集を禁止する。ただし親セッションの実行時権限が設定を上書きする
場合があるため、スキルは実効的なread-only sandboxを使えない場合に逐次レビューへ
フォールバックする。修正は主エージェントが利用者の依頼範囲を確認して別工程で行う。
