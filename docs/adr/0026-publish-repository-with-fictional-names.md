# ADR 0026: 公開に備えて実在の名前とゲーム名を伏せ、本物のチームマスタをGit管理外に置く

- 状態: 提案中
- 日付: 2026-10-19
- 置き換え: ADR 0011のうち、volume名。ADR 0021のうち、名前空間の名前と、配布名とCLI名を当面維持するとした点。ADR 0024のうち、秘密情報の範囲。
  Git管理外のチームマスタにある集結主名、代理集結主名、役割、運用メモを加える。READMEと同梱の
  `team_master.json`に載る名前を対象外とする点は維持する
- 訂正（2026-10-25）: 公開Repositoryは`drrrkawasaki`ではなく`kakeoProduct`のアカウントの下に作られ、
  `web/`の実際の公開先は`https://kakeoproduct.github.io/KvK-Team-Builder/web/`である。本文の旧URLは
  404を返す（2026-10-25に確認）。判断の記録として本文は書き換えない。旧Repositoryも同じ`kakeoProduct`の
  アカウントにあるため、ブラウザの保存先のoriginが変わらず、保存した入力が残るという結論は変わらない

## 背景

GitHub ActionsのCIを無料で使い続けるため、Repositoryを公開し、開発の拠点を公開Repositoryへ
移す。現在のRepositoryには、公開したくない情報が含まれている。

- 同梱の`team_master.json`、README、`sample/`、`tests/`に、集結主と代理集結主の実在の名前と、
  チームごとの役割の割り当て、作戦を書いた運用メモ
- READMEの入力例、`sample/`、`tests/`に、ほかの参加者の実在の名前と同盟名
- `web/`の補助ツールの初期値と、その要件定義書の例に、参加者の実在の名前と同盟名
- パッケージ名、配布名、CLI名、文書、`web/`のファイル名と表示に、ゲーム名とイベント名。
  利用者は、ゲーム名で検索してこのRepositoryが見つからないことを求めた
- `web/`の作業メモとチェックログに、個人の作業フォルダ名とサーバー番号

公開すると、敵対する王国を含む誰でも、誰がどのチームでどの役割を担うかを読める。いまの
RepositoryをそのままPublicにすると、Git履歴、Issue、Pull Requestのコメントも公開される。
履歴を書き換えるforce pushは禁止している。

一方、運用では本物の集結主と役割を書いたチームマスタが必要になる。CLIは同梱のファイルだけを
読み込み、ほかのファイルを指定する方法がなかった。

## 判断

- 実在の名前と同盟名を、追跡するすべてのファイルで架空の名前へ置き換える。名前の種類
  （漢字、ひらがな、カタカナ、英字）と、プレースホルダー（`SKY01`など）の形式は保ち、
  記法の検証が弱まらないようにする
- 同梱の`team_master.json`は公開用の例とし、集結主、代理集結主、役割、運用メモを架空にする
  （役割は`役割A`〜`役割K`、運用メモは`運用メモの例`）。イベント時間、人数、VC、戦力関係は
  現行のままにする。`tests/test_team_master_repository.py`が、役割と運用メモが仮の表記であることを検査する
- CLIへ`--team-master <path>`を加える。省略すると同梱の例を使い、付け忘れに気づけるよう
  標準エラーへ注意を出す。指定すると、`interfaces/cli/composition.py`の`default_rules`が同じ
  `JsonTeamMasterRepository`で読み込む。読み込めない場合は、既存の`TeamMasterLoadError`として
  終了コード2で終わり、出力を書かない。本物のファイルは手で編集するため、各項目の型（文字列、整数、
  真偽値、文字列の配列）、欠けた項目、書き間違えた未知の項目、時刻の形式も確かめ、どのチームの
  どの項目かを示す読み込みエラーにする。本物の名前が不具合報告へ漏れないよう、エラーには値ではなく
  型名だけを出す
- 本物の集結主、代理集結主、役割、運用メモを書いたチームマスタと、本物の参加者一覧、出力は
  Git管理外の`tmp/`に置き、コミットしない。コミットメッセージ、branch名、Pull Requestのタイトルと
  本文、Issue、レビュー結果とコメントへも書かない。この規則（伏せる語の規則）は`AGENTS.md`の1か所に
  置き、`$implement`、`$create-github-pr`、`$manage-github-issue`、`$review-kvk-change`、`$change-kvk-rules`、
  `kvk-requirements-reviewer`から参照する。`skills-lock.json`で管理する外部Skill（Issueを作る
  `to-tickets`、`triage`、`to-spec`、`wayfinder`、branchやコミットを作る`prototype`、
  `resolving-merge-conflicts`など）はローカルで書き換えないため参照を加えず、常に読み込まれる
  `AGENTS.md`の規則に従う。Pull RequestとIssueのテンプレートにも、人が画面から書く場合に備えて同じ注意を書く
- ゲーム名とイベント名を、追跡するすべてのファイルから除く。パッケージ名は`kvk_team`、
  配布名とCLI名は`kvk-team-builder`、Dev Containerの拡張機能volumeは`kvk-vscode-extensions`、
  共有記憶の一時状態Directoryは`kvk-team-builder-memory`とする。`web/`の攻城タイムライン計算は
  ファイル名と表示名からイベント名を除く。KvKは多くのゲームで使う一般的な用語のため残す。
  `web/`のCSSクラスと保存キーの接頭辞`ks`も、単独では検索の手掛かりにならず、保存キーを変えると
  サイドバーの開閉状態が消えるため残す（作成者の仮定）
- 過去のADRと共有記憶にある識別子（パッケージ名、配布名、CLI名、volume名、Directory名）と
  ゲーム名とイベント名も、伏せる語を除いた表記か、本ADRで改名した後の名前へ書き換える。当時の表記は、アーカイブした旧Repositoryの
  履歴に残る。これは`docs/adr/README.md`の「採用済みADRを直接書き換えない」の例外で、伏せる語と
  識別子の表記の書き換えと、書き換えたことを示す注記だけに限る。規則どおりに新しいADRから参照するだけでは、公開Repositoryに伏せる語が
  残るためである。書き換えたADRは0011（採用済み）、0021、0023である。0011と0023は表記の書き換え（0011では、冒頭の「置き換え」に挙げたvolume名の表記）と注記だけで、判断の内容は変えていない。0021は表記の書き換えに加え、本ADRで置き換えた点（名前空間、配布名、CLI名）を状態と本文に注記した。0024は状態の更新だけである。
  `web/`の作業メモとチェックログは、個人の作業フォルダ名、サーバー番号、移動済みのランキング系の
  ファイルの記述を除き、経緯の要約だけを残す
- `tests/test_repository_scope.py`が、追跡するファイルのパスと内容に伏せる語がないことを、
  大文字と小文字、全角と半角、区切り文字の違いをなくして検査する。検査自身が当たらないよう、
  語はコードポイントで持つ。実在の名前は一覧をRepositoryに置けないため、この検査の対象外とする
- 公開は、この変更を取り込んだ`main`の内容を、履歴のない新しい公開Repository
  `KvK-Team-Builder`へ載せて行う。公開Repositoryは同じアカウント（`drrrkawasaki`）の下に作る
  （作成者の仮定）。いまのRepositoryは非公開のままアーカイブし、履歴の保管先にする。
  内容は`git archive main`のように追跡するファイルだけから作り、Git管理外の`tmp/`（本物のチームマスタや
  レビューの出典）を持ち込まない。新しいRepositoryの説明とtopicsにも伏せる語を書かない
- 文書の`#番号`は、アーカイブした旧Repositoryの番号を指す。新しいRepositoryのIssue、Pull Request、
  コメント、コミットメッセージへ`#番号`を写すと、GitHubが新しいRepositoryの項目へ自動でリンクするため、
  写すときは旧Repositoryの番号であることを書き添える

## 代替案

### いまのRepositoryをそのまま公開する

置き換えても、過去のコミット、Issue、Pull Requestのコメントに実在の名前とゲーム名が残る。
履歴の書き換えはforce pushが必要で、規約で禁止しているため採用しない。

### 非公開のまま使う

名前は公開されないが、CIの無料枠（月2,000分、Windowsは2倍で数える）を使い切る懸念が残る。
利用者が公開を選んだため採用しない。

### 本物のチームマスタを環境変数や既定の場所から自動で読む

指定を省けるが、どのマスタで編成したかが実行コマンドから見えなくなる。テストや同梱の例の
実行が、手元のファイルの有無で変わるおそれもあるため、明示的なオプションにする。

### KvKも伏せる

KvKはクラス名、Skill名、Review Agent名、Webツールのファイル名とブラウザの保存キーに使われ、
変更量が約2倍になる。保存キーを変えると、各自がWebツールに保存した入力が消える。一般的な
用語で検索の手掛かりになりにくいため、利用者は伏せないことを選んだ。

## 影響

- 運用者は毎回`--team-master`を指定する。付け忘れると、架空の集結主で編成され、全チームに
  集結主の到着待ちの警告が出る。本物の参加者に架空名と同じ名前の人がいれば、その人が固定
  集結主として置かれ、警告も出ない。標準エラーの注意で付け忘れに気づけるようにした
- 本物のチームマスタはCIで検証されない。同梱の例でイベント時間、人数、VC、戦力関係が
  変わったときは、運用者が本物のファイルへ同じ変更を反映する。イベントの前に`--team-master`付きで
  一度実行し、読み込みエラーがないことを確かめる
- `tmp/`のファイルはRepositoryの再作成やCodespaceの作り直しで消えるため、本物のチームマスタは
  利用者が別に保管する
- `tools/preview_output.py`は同梱の例と`sample/`で確認する用途のため、`--team-master`は加えない
- pushの前の伏せる語の検査（`$create-github-pr`の「Pull Requestの対象を検証する」の手順5）はHEADの内容だけを見る。途中のコミットで
  加えて後で消した語もpushで公開されるが、`<base>...HEAD`の各コミットの差分を機械で検査する仕組みは
  この変更では作らず、作成者が目で確かめる。利用者がレビューの`Should`の見送りを選び（2026-10-19）、
  公開後の最初のPull Requestで`tools/`へ検査のScriptを加える。最初の公開は履歴を持たない内容から作る
  ため、この限界の影響を受けない
- パッケージ名、配布名、CLI名が変わるため、手元の環境は旧配布物を`pip uninstall`してから
  `python -m pip install -e ".[dev]"`で入れ直す。旧配布物を残すと、旧CLI名のコマンドがPATHに残り、
  実行するとImportErrorになる。Dev Containerの拡張機能volumeは名前が変わるため、初回に拡張機能を
  取得し直す
- 共有記憶の一時状態Directoryの名前が変わるため、変更前に`start`したSessionの開始状態は
  新しい場所から見えない。変更をまたぐSessionは、開始状態を移すか`start`し直す
- Repositoryの移動で、`web/`の全ツールのGitHub PagesのURLが
  `https://drrrkawasaki.github.io/KvK-Team-Builder/web/`の下へ変わる。攻城タイムライン計算はファイル名も
  変わる。共有済みのURLは移動後に案内し直す。ブラウザの保存キーは変えないが、保存先はURLのoriginごとに
  分かれる。originは`drrrkawasaki.github.io`のまま変わらないため、保存した入力は残る
- 新しいRepositoryでGitHub Pagesを有効にしてから、旧RepositoryのPagesを無効にする。旧Repositoryの
  Pagesはアーカイブしても公開が止まらないため、アーカイブの前に無効にする
- CodespacesのSecret`GH_TOKEN`は旧Repositoryに限定したfine-grained PAT（ADR 0008）のため、新しい
  Repository向けに作り直す
