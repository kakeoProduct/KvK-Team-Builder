# ADR 0020: ブラウザ用補助ツールの要件定義書を要件の正本とする

- 状態: 提案中
- 日付: 2026-10-17

## 背景

`web/`の単体HTMLツールは、ADR 0013で計算ロジックの正本を各HTMLとし、Pythonの品質ゲートの
対象外とした。ツールの経緯と変更履歴は`web/WORK_STATUS.md`に記録されているが、何が意図した
振る舞いで何が不具合かを判断する基準がない。今後ツールを修正するにあたり、修正前に期待する
振る舞いを合意し、修正後に確認できる根拠が必要になった。

## 判断

- `docs/requirements/web-tools/`に要件定義書を置き、`web/`のツールの要件の正本とする
- 各HTMLは引き続き実装の正本とし、要件定義書とHTMLの食い違いは利用者が判断して同じ変更で
  そろえる
- 要件、既知の不具合、未決事項にIDを付け、修正の単位として参照できるようにする
- 初版は現行のHTMLから書き起こし、意図と異なる振る舞いを既知の不具合、意図が不明な振る舞いを
  未決事項へ分ける
- `web/WORK_STATUS.md`は経緯の記録として残す
- `web/`直下の各HTMLが要件定義書に載っていることを構造テストで確かめる

## 代替案

### `web/WORK_STATUS.md`を要件の記録として使い続ける

追加の文書は不要だが、作業の経緯と現在の要件が混ざり、どの記述が有効かを読み手が判断する
必要がある。要件を参照するIDもないため採用しない。

### HTMLの振る舞いを自動テストで固定する

回帰を機械的に検出できるが、ADR 0013のとおりCIへNode.jsとブラウザの実行環境を追加する
必要がある。現行の振る舞いには不具合が含まれ、先に期待値を合意する必要があるため、現時点では
採用しない。

## 影響

ツールを修正するときは、要件定義書の更新が先になる。要件定義書の内容はPythonの品質ゲートで
検証されないため、HTMLとの一致はレビューとブラウザでの動作確認で担保する。構造テストは
ファイルの対応だけを確かめ、要件の中身は確かめない。
