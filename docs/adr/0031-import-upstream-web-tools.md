# ADR 0031: ブラウザ用補助ツールを取り込み元の版へ置き換え、外部サーバーとの連携を外す

- 状態: 提案中
- 日付: 2026-11-03
- 置き換え: ADR 0030のうち、`tests/web/`が検査する集結タイムライン計算の性質C4〜C7とタブ、周期ウェーブタイマーの
  計算元の読み込み。検査を品質ゲートに含める方式は維持する

## 背景

`web/`の補助ツールは、ある利用者が個人のRepositoryで作ったHTMLを、名前を伏せて取り込んだものである
（ADR 0026）。その後、取り込み元のRepository（以下、取り込み元）と、このRepositoryの両方で、同じツールが
別々に変わった。取り込み元の名前とURLは伏せる語を含むため、文書には書かない。所有者からは取り込みの許可を
得ている（利用者の確認、2026-11-03）。

- 取り込み元: 速度ペットのボーナス、増援をパターンごとに選ぶ、計算結果をパターンごとのブロックで出す、
  計算結果を周期ウェーブタイマーへ自動で渡す、周期ウェーブタイマーの発起時刻を過ぎた人の表示と時短の候補、
  カウントダウン表の役割、遅延秒数、相手の名前、名簿のタブ、占領判定のリセットを加えた。加えて、
  Google Apps Script（以下、GAS）の中継役を使う共有データ、イベントの選択、パスワードによる編集可モード、
  登録者からの名簿の取り込み、相手の名簿の読み込みを加えた
- このRepository: 集結タイムライン計算と周期ウェーブタイマーにページ内のタブと計算元の選択を加え、
  1周目を繰り返すと待ち時間を破る周期の計算を直した（`siege-timeline.md`の旧SIEGE-013、SIEGE-017、
  SIEGE-021）。`tests/web/`の検査で、性質C1〜C10を確かめていた

取り込み元のGAS連携は、要件COM-001（外部のサーバーを使わない）に反する。GASのURL、共有データにある
参加者の実名と同盟名、相手のサーバーの名簿は、公開Repositoryへ載せられない（ADR 0026）。

## 判断

- 範囲は、取り込み元のツールの7ページ（メニューを含む）と、速度ペットの共通部品だけとする。管理画面、
  参加登録、チーム分け、問い合わせ、ランキング、相手との突合せ、GASのScript、GitHub Actionsは取り込まない
- 集結タイムライン計算、周期ウェーブタイマー、カウントダウン表は取り込み元の版で置き換える（利用者の判断）。
  占領判定はリセットだけを移す。カウントアップ表と音声ストップウォッチは取り込み元でサイドバーしか
  変わっていないため、このRepositoryの版を残す
- GASとの連携（共有用の表示、イベントの選択、共有への保存、編集可モード、登録者の名前と同盟名の候補、
  登録者からの取り込み）と、相手の名簿の読み込みは外し、「このブラウザだけ」に保存する動作だけを残す
- 速度ペットのボーナスの編集は、取り込み元と同じく`web/pet-bonus.js`の共通部品とする。COM-001を
  「各ページのHTMLと、`web/`に置く共通部品だけで動く」へ改める。2つのページで同じ値を使うため、
  HTMLへ複写しない
- ゲーム名、イベント名、ペットのスキル名は除く（ADR 0026）。メニューのグループ名は、イベント名の代わりに
  「攻城」とする。周期ウェーブタイマーの自動取り込みの通知文は、取り込み元では集結タイムライン計算を別の名前で
  呼んでいたため、表示名（COM-020）にそろえて「集結タイムライン計算」とする。カウントアップ表と音声ストップウォッチは、取り込み元と同じくメニューとサイドバーから外し、
  ファイルは残す
- このRepositoryで加えたタブ、計算元の選択、周期の修正は失う。失った項目は各要件定義書の「決定済みの事項」に
  列挙し、運用に影響するものは既知の不具合（KI-SIEGE-14〜17、KI-SIEGE-19、KI-WAVE-15、KI-WAVE-18、KI-WAVE-19、KI-WAVE-21、
  KI-WAVE-28、KI-WAVE-29）として記録する。必要になったら取り込み元の版の上で改めて直す
- 公開済みの版で周期ウェーブタイマーの`waveTimerTabs`に保存したタブの設定とタイムラインは、新しい版でタブを
  操作した時点で戻せない形で上書きされる。利用者はこの消失を受け入れた（2026-11-03）。中身の多くは集結
  タイムライン計算から作り直せる。HTMLは変えない
- `tests/web/`は、新しい要件定義書の要件を確かめる検査へ作り直す。取り込み元の周期の計算が満たさない
  性質（旧C5〜C7）は、検査から外して既知の不具合へ記録する。検査を弱めて品質ゲートを通すのではなく、
  要件そのものを利用者の判断で変えたためである。旧C4（2周の着弾の順番が同じ）も、2周目を計算し直すため
  ブロックの並びが周ごとに変わり得ることから外す。利用者は続けて、取り込んだ版の動作を正とし、仕様書と検査を
  それに合わせ、HTMLは変えないと決めた（2026-11-03）

## 代替案

- **このRepositoryの版を土台に、取り込み元の機能を移す:** 周期の修正と検査を保てるが、作業量が最も多い。
  作成者はこれを推奨したが、利用者は取り込み元の版で置き換えることを選んだ
- **GAS連携ごと取り込む:** 取り込み元と同じ運用ができるが、COM-001に反し、GASのURLが公開Repositoryに載る。
  共有データの実名を守る方法も別に要る
- **競合しない5ページだけを取り込む:** 競合する2ページの判断を後へ回せるが、利用者が取り込みたい機能の
  多くが2ページにある

## 影響

- 集結タイムライン計算の周期は、2周目を計算し直した最初のパターンの着弾の差に戻る。1周目を周期ごとに
  繰り返すと、待ち時間を破る指示を出すことがある（KI-SIEGE-14）。周期ウェーブタイマーは1周目を繰り返す
  前提のため、運用者は「計算結果（1周目）」で人ごとに`最初の発起 + 周期 >= 最後の帰還 + パターン間バッファ`を
  確かめる。満たす人は待ち時間を守る。満たさない人は、周期ウェーブタイマーの2個目以降の予定で、待ち時間
  （帰還 + パターン間バッファ）より前の発起を指示されるおそれがある（KI-SIEGE-14の見分け方）
- 周期ウェーブタイマーの時短のボタンは、計測中にDesktopのマウスで押しても効かないことがある（KI-WAVE-30）。
  確実に選ぶにはタッチの端末を使う。ストップすると以降の予定が止まり、再スタートで最初からになる（WAVE-021、
  WAVE-022）ため、作戦中の回避策にはならない
- カウントダウン表は、到着秒数が空欄の行を0秒として計算に含めるようになった。置き換える前の版は除外していた
  （KI-CDOWN-11、Q-CDOWN-05）
- 置き換えた3ページは保存キーと形式が変わり、このRepositoryの版で保存した内容の一部を読まない。
  集結タイムライン計算はタブの保存データ（`siegeCalcTabs`）を読まず、タブを加える前の`siegeCalcState`を
  表示する。周期ウェーブタイマーは`waveTimerTabs`の形式が違うため読まず、タブを加える前の設定と
  タイムライン（`waveTimerSettings`、`waveTimerPastedTimeline`）を1つ目のタブに表示する。タブを操作すると
  `waveTimerTabs`を新しい形式で上書きする。
  カウントダウン表は新しいキー`kvkCountdownRosterStateV2`を使い、旧キーの名簿を読まない。
  `siegeCalcTabs`と`kvkCountdownRosterState`は読まれも消されもせずブラウザに残るため、元の版へ戻せば表示できる
- 速度ペットの共通部品が読めないと、集結タイムライン計算とカウントダウン表は動かない。HTMLを1ファイルだけ
  保存して使う場合は、`pet-bonus.js`も同じフォルダに置く必要がある
- 外部のサーバーへ通信しなくなるため、共有データ、イベント、登録者の情報はこの版では使えない
- 取り込み元の更新を再び取り込む場合は、本ADRの範囲と除く連携を基準に、取り込み元の差分を確かめる
