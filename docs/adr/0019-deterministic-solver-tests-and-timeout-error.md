# ADR 0019: CP-SATのテストを決定的時間で打ち切り、時間切れを解の不存在と区別する

- 状態: 提案中
- 日付: 2026-10-17

## 背景

CIのwindows-latest／Python 3.12で、編成を最適化する3件のテストが「全時間帯の必須条件を
満たす編成が見つかりませんでした」でまれに失敗した。同じcommitの別のCI実行では成功していた。

テストは`maximum_optimization_seconds=5.0`の実時間制限と、既定の8 workerによる並列探索を
使用していた。手元で次を確認した。

- 制限時間を0.6秒にすると、88人の動的編成は3回中3回、同じ例外で失敗する。Solverの状態は
  `UNKNOWN`（時間切れ）であり、`INFEASIBLE`（解なし）ではない
- 1コアへ6本のCPU負荷を加えると、5秒・8 workerの設定でも3回中3回失敗する
- 実時間で打ち切ると、1 workerでも実行ごとに目的値が変わる。1 workerかつ決定的時間1.0で
  打ち切ると、CPU数を1コアへ制限しても目的値が一致する

並列探索は`random_seed`を固定しても、worker間の結果共有が実時間に依存するため決定的に
ならない。また、Optimizerは`UNKNOWN`と`INFEASIBLE`を同じ例外にしており、利用者も
開発者も、参加者の見直しが必要なのか再実行で足りるのかを判断できなかった。

## 判断

- `KvKRules`へ任意の`maximum_deterministic_time`を追加する。指定時は、Optimizerが
  CP-SATの`max_deterministic_time`へ渡す。未指定時の既定動作は変えない
- CP-SATを実行するテストは`tests/deterministic_solver.py`の`deterministic_rules()`を使い、
  1 worker、決定的時間1.0、停止しない場合だけを防ぐ実時間120秒で実行する
- Optimizerは`INFEASIBLE`を`InfeasibleRosterError`、`UNKNOWN`を`OptimizationTimeoutError`へ
  変換する。どちらも`OptimizationError`の派生とし、CLIの捕捉と終了コード2を維持する
- 時間切れのメッセージは、編成が存在しないとは確定していないことと、制限時間を明示する

## 代替案

- テストの実時間制限を延ばす: 失敗の頻度は下がるが、Runnerの負荷次第で再発し、
  目的値も実行ごとに変わるため採用しない
- テストを最初の実行可能解で打ち切る: 決定的にできるが、目的関数による編成の質を
  テストで確認できなくなるため採用しない
- 8 workerのまま決定的時間で打ち切る: 並列時は決定的時間の上限が厳密に守られず、
  結果の共有も実時間に依存するため採用しない
- 時間切れをサービス層で自動再試行する: 混んだ環境では再試行も時間切れになりやすく、
  実行時間が倍増する。まず原因を区別して表示する

## 影響

- テストの結果は実行環境の速さと負荷に依存しなくなる。OR-Toolsを更新すると探索の経路が
  変わり得るため、更新時に決定的時間の余裕を確認する
- 1 workerのため、テストは既定の並列探索の振る舞いを検証しない。並列設定の影響は
  `python tools/preview_output.py`で確認する
- 利用者向けのエラーメッセージが原因ごとに変わる。CLIへ制限時間のOptionはないため、
  時間切れの対処は再実行とする
