# ADR 0005: Apple設計原則をWeb UI基準として採用

- 状態: 採用
- 日付: 2026-07-20

## 背景

現行製品はCLIとMarkdown出力を提供し、将来のWeb UIをAdapterとして追加する方針である。
一方、画面の情報階層、状態表現、操作Feedback、Animation、文字組み、アクセシビリティに
共通の判断基準がなく、UI実装者ごとに操作感と品質が変わる可能性がある。編成結果と警告を
扱う運用Toolでは、装飾より予測可能性、可読性、回復可能性を優先する必要がある。

## 判断

- Emil Kowalskiの`apple-design`スキルをリポジトリ共有の
  `.agents/skills/apple-design`へ導入し、日本語化とプロジェクト固有の補足を行う
- Web UIの新規実装、変更、レビューでは`$apple-design`を使用する
- Apple製品の外観模倣ではなく、目的、主体性、責任、親しみやすさ、柔軟性、単純さ、
  作り込み、喜びを判断原則として採用する
- 即時Feedback、予測可能な空間関係、中断可能な動き、読みやすい文字組み、節度あるMaterialを
  実装基準とする
- Keyboard、Focus、文字拡大、低モーション、低透明度、高Contrastを同じUI変更で確認する
- 警告と必須条件エラーを色だけで区別せず、UIへKvKのドメインルールを複製しない
- 主要なUI FrameworkまたはAnimation Libraryの追加は、この判断だけで許可せず、必要性と
  代替案を別のADRへ記録する

導入元はMIT Licenseであり、上流の著作権表示とLicense本文をスキルDirectoryへ保持する。

## 代替案

### 個人環境へだけスキルをインストールする

リポジトリを利用する他の開発者とAIエージェントへ基準が共有されず、版管理もできないため
採用しない。

### Apple Human Interface Guidelinesを見た目の仕様として直接模倣する

Web、Desktop、Mobileで利用状況が異なり、外観の模倣はこの製品の情報量や運用目的を
損なう可能性がある。原則をWebの技術と製品文脈へ翻訳する方針を採用する。

### UI実装時に都度デザインを決める

初期コストは小さいが、状態表現、Animation、アクセシビリティの判断が一貫せず、Reviewで
再現可能な基準を持てないため採用しない。

## 影響

今後のWeb UI変更は、機能テストに加えて主要状態、KeyboardとFocus、文字拡大、低モーション、
低透明度、高Contrast、MobileとDesktopの目視確認が必要になる。高度なGestureやMaterial表現を
無条件に求めるものではなく、利用基盤の制約下では即時Feedback、明確な状態、可読性を優先する。
上流スキルを更新する場合は、日本語化した追加規則とLicense表示を維持し、変更内容をReviewする。
