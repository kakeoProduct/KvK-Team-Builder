# ADR 0001: 開発方針ハーネス

- 状態: 採用
- 日付: 2026-07-19

## 背景

リポジトリには責務分離されたPython実装、pytest、GitHub Actionsが存在する一方、
開発判断の正本、静的品質チェック、複数OSで共通の完了条件が定義されていなかった。
人間とAIエージェントが同じ基準で安全に変更できる仕組みが必要である。

## 判断

- 現在のREADME、アーキテクチャ、実装、テストで一致する振る舞いを現行仕様とする
- `AGENTS.md`を人間とAIエージェントが共通で従う開発ルールとする
- `DEVELOPMENT.md`に再現可能な開発手順を置く
- `python tools/check.py`をローカルとCIの共通品質ゲートとする
- Ruff、mypy、pytestを必須チェックとする
- WindowsとLinux、Python 3.11と3.12を正式対応環境とする
- 重要な方針変更はADRとして記録する

## 代替案

### 文書だけで運用する

導入は軽いが、フォーマット、型、テストの実行漏れを自動検出できないため採用しない。

### OSごとにシェルスクリプトを用意する

同じロジックが重複し、WindowsとLinuxで品質ゲートがずれるため採用しない。

### CIだけで検査する

フィードバックが遅く、ローカルでCIと同じ確認を再現しにくいため採用しない。

## 影響

変更完了までに静的検査と全テストの成功が必要になる。開発依存は増えるが、1つの
PythonコマンドでOSを問わず実行できる。正式対応環境を増やすためCIジョブ数は増える。
