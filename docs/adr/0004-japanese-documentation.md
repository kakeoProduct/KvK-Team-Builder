# ADR 0004: 文書とコミットメッセージの日本語統一

- 状態: 採用
- 日付: 2026-07-19

## 背景

利用者と主な開発者は日本語で要件と運用を共有している一方、共有スキルとカスタム
エージェントの
説明が英語で作成されていた。文書やコミットメッセージごとに言語が異なると、プロダクト
ルールや変更履歴、レビュー指摘の理解に余計な負担がかかり、同じ概念へ異なる訳語が
使われる危険がある。

## 判断

- Repositoryで管理する見出し、説明、手順、判断理由は原則として日本語にする
- スキルの説明・本文・既定プロンプトと、カスタムエージェントの説明・指示も日本語にする
- コード識別子、設定キー、パス、コマンド、製品・ライブラリ・規格の固有名詞は公式表記を保つ
- License、外部資料の引用、ツール出力は翻訳対象外とする
- コミットメッセージは`type(scope): 日本語の要約`を基本形とし、Conventional Commitsの
  `type`と任意の`scope`は英語、要約と本文は日本語にする
- スキルとエージェントの主要な説明値が日本語を含むことを自動テストする
- レビュー担当は新規・更新文書に英語だけの説明段落がないか確認する

## 代替案

### 日本語と英語を文書ごとに自由選択する

作成時は容易だが、用語と理解コストが揃わないため採用しない。

### すべてを日本語へ翻訳する

コード識別子や外部仕様のKeyまで翻訳すると、実装との対応やTool互換性を損なうため
採用しない。

### 日英を常に併記する

文書量が増えて保守時に内容がずれるため、必要な技術用語の初出に限って併記する。

## 影響

新規文書、変更履歴、レビュー結果の可読性が揃う。外部仕様とコードの検索性を保つため、
機械的な識別子とコミット種別は英語表記のまま残る。既存の固有名詞を機械的に翻訳しない
判断が必要になる。
