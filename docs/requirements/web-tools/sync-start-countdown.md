# 要件定義: KvK同着スタート カウントダウン表

| 項目 | 内容 |
|---|---|
| 対象ファイル | `web/KvK同着スタート カウントダウン表.html`、`web/pet-bonus.js`（速度ペットの共通部品） |
| 表示名 | 「KvK同着スタート カウントダウン表」 |
| 状態 | 稼働中 |
| 要件ID接頭辞 | `CDOWN` |
| 現行仕様の確認日 | 2026-11-03（取り込み元の版へ置き換えた後のコードの読解による。共通部品の読み込み、初期表示の計算、タブの複製、横にはみ出さないことは、Chromium 130でDesktop幅（1280px）とMobile幅（390px）で確認（COM-053）。速度ペットのボーナスを集結タイムライン計算と共有することは`tests/web/`で確認。ADR 0031） |

取り込み元の版へ置き換えたことで、名簿の項目、グループ、保存の形式が
[KvK同着スタート カウントアップ表](sync-start-tables.md)と別のものになった。このため、置き換える前に
共通の文書で定めていたカウントダウン表の要件（SYNC-001〜SYNC-061のうちカウントダウン表に関するもの）を
本書へ移した。

## 1. 目的と利用場面

行軍時間が異なる複数のメンバーが、目標へ同時に到着できるよう、各自の出発タイミングを秒単位で
示す。行軍が最も長いメンバーが最初に出発し、短いメンバーほど待ってから出発する。最後に出発する
メンバーを0秒とし、残り秒数で出発順を示す。結果は一覧表と、ゲーム内チャットへ貼り付けるテキストで
出力する。名簿はタブで複数の案を持てる。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 到着秒数 | メンバーが出発してから目標に着くまでの行軍秒数（速度ペットなし） |
| 遅延秒数 | 到着秒数へ加える0以上の秒数 |
| 速度ペット、採用 | [集結タイムライン計算](siege-timeline.md)と同じ。行軍を縮めるペットと、その秒数を使うか |
| 実際秒数 | 計算に使う到着までの整数秒（CDOWN-011） |
| グループ | 同着させたい単位。同じ文字列を入力したメンバーを同じグループとみなす |
| 未所属 | グループ欄が空、`ー`（全角長音）、`未所属`、`-`（半角）、`なし`のいずれか |
| 相手 | そのメンバーが対応する敵のプレイヤー。名前と秒数を控えとして表示する |
| 最後の出発カウント | `実際秒数の最大値 - 実際秒数の最小値` |

## 3. 機能要件

### 3.1 名簿の入力

| ID | 要件 |
|---|---|
| CDOWN-001 | 名簿は1行1メンバーで、「名前」「役割」「到着秒数（ペットなし）」「遅延秒数」「速度ペットLv」「採用」「グループ」「相手の名前」「相手の秒数」を入力できる。「到着秒数（ペットあり）」は読み取り専用で、速度ペットがなければ「（ペットなし）」、あれば`到着秒数 ÷ (1 + ボーナス ÷ 100)`を四捨五入して表示する |
| CDOWN-002 | 役割は「（未設定）」「王城メイン」「王城ゴースト」「砲台」から選ぶ。「王城メイン」は1人だけとし、選ぶとほかの行の「王城メイン」を「（未設定）」へ戻す。役割は計算と出力に使わない |
| CDOWN-003 | 遅延秒数は0未満を0とする |
| CDOWN-004 | 「速度ペットLv」の選択肢と、Lvごとのボーナスの編集は、集結タイムライン計算のSIEGE-007、SIEGE-009と同じとし、同じ値（SIEGE-046）を使う。ボーナスを変えると名簿を表示し直し、結果を表示していれば計算し直す |
| CDOWN-005 | グループ欄は、名簿で入力済みの未所属以外のグループを候補に出す |
| CDOWN-006 | 「＋行を追加」で空行（名前空、役割未設定、到着秒数0、遅延秒数0、速度ペットなし、採用オン、グループ空、相手空）を末尾へ追加でき、各行の「削除」でその行を削除できる |
| CDOWN-007 | 「最大カウント秒」で表に出すカウントの上限を指定できる。既定値は120、入力欄の範囲は1〜600 |
| CDOWN-008 | 表示中のタブに保存した名簿がないか、0行の場合は、確認用のサンプル名簿5行を表示する |

### 3.2 計算規則

| ID | 要件 |
|---|---|
| CDOWN-010 | 名前の前後の空白を除き、名前が空の行は計算から除外する。到着秒数と遅延秒数は、空欄または数値でない入力を0秒として計算に含める |
| CDOWN-011 | 実際秒数は、採用がオンなら`到着秒数 ÷ (1 + ボーナス ÷ 100) + 遅延秒数`、オフなら`到着秒数 + 遅延秒数`を四捨五入した整数とする |
| CDOWN-012 | 全体の基準を実際秒数の最大値とし、カウント`c`の行には実際秒数が`全体の基準 - c`のメンバーを出す |
| CDOWN-013 | グループは未所属以外の値を名簿の出現順に重複なく列挙する。グループの基準はそのグループの実際秒数の最大値とし、カウント`c`の行のグループ列には、そのグループで実際秒数が`グループの基準 - c`のメンバーを出す |
| CDOWN-014 | 1列目の値は`最後の出発カウント - c`とする。行は`c = 0`から`min(最大カウント秒, 最後の出発カウント)`までとする |
| CDOWN-015 | 最大カウント秒が0、空欄、数値以外の場合は120として扱う |
| CDOWN-016 | 計算はページ表示時、タブの切り替え時、「計算する」押下時、速度ペットのボーナスの変更時（結果を表示しているとき）に行う。名簿の入力だけでは計算し直さない |

### 3.3 出力

| ID | 要件 |
|---|---|
| CDOWN-020 | 結果表の列は「最後の出発まで」「全体」、グループごとの「{グループ名}」とする。1列目の値が0の行を強調表示する |
| CDOWN-021 | 該当者は「、」で連結して強調表示し、いない場合は「なし」と表示する |
| CDOWN-022 | 該当者は、相手の名前も相手の秒数も空なら名前だけで表す。どちらかがあれば、相手の秒数があるとき`{名前}（vs {相手の名前} {相手の秒数}秒）`、ないとき`{名前}（vs {相手の名前}）`と表す。相手の名前が空なら`?`とする |
| CDOWN-023 | チャット用テキストは「全体」とグループごとに1つずつ作り、「チャット用テキスト：{全体またはグループ名}」の見出しを付ける。該当行だけを1列目の値の降順で`{値}秒：{該当者}`と並べ、前後を`ーー`の行で囲む。該当者がいなければ本文を「（到着者なし）」とする |
| CDOWN-024 | 有効な行が0件の場合、結果表に「名簿を入力してください」と表示し、チャット用テキストを出さない |

### 3.4 操作

| ID | 要件 |
|---|---|
| CDOWN-030 | チャット用テキストごとに「コピー」ボタンを置き、クリップボードへコピーできる。クリップボードへの書き込みに失敗した場合は、テキストを選択してブラウザのコピーを試みる。コピー後は1.2秒間、ボタン表示を「コピーしました」に変える |
| CDOWN-031 | チャット用テキストは手で編集できる |

### 3.5 タブ

| ID | 要件 |
|---|---|
| CDOWN-040 | ページ内のタブで複数の名簿を切り替えられる。各タブは名簿を独立に持つ。最大カウント秒と速度ペットのボーナスはタブで共通とする |
| CDOWN-041 | 「+」で空の1行だけの名簿のタブ「名簿{追加前のタブの数 + 1}」を、「このタブを複製」で表示中の名簿を写したタブ「{表示中のタブの名前}のコピー」を末尾へ追加して表示する |
| CDOWN-042 | タブの名前は、タブの上の欄で直接変更できる。タブをクリックすると、そのタブを表示して計算する |
| CDOWN-043 | タブの「×」で、そのタブと保存した名簿を削除できる。削除の前に確認を出し、取り消した場合は何も変えない。タブが1つだけの場合は「×」を出さない。表示中のタブを削除した後は、先頭のタブを表示する |

### 3.6 保存

| ID | 要件 |
|---|---|
| CDOWN-050 | 名簿を入力、行の削除、タブの追加のたびに、表示中のタブのキーへ`{rows, rowSeq}`として保存し、次回表示時に復元する。`rows`の各行は`{id, name, role, march, adj, petLevel, usePet, group, opponentName, opponentSec}`とする。計算結果は保存しない |
| CDOWN-051 | 最初のタブ（`id`が`default`、名前「名簿1」）はキー`kvkCountdownRosterStateV2`、ほかのタブは`kvkCountdownRosterStateV2_{id}`を使う。タブの一覧（`[{id, title}]`）をキー`kvkCountdownTabs`へ、最後に表示していたタブの`id`を`kvkCountdownCurrentTab`へ保存する |
| CDOWN-052 | 最大カウント秒を入力のたびにキー`kvkCountdownMaxSec`へ保存し、次回表示時に復元する |

## 4. 既知の不具合と現行実装との差異

| ID | 内容 | 影響 |
|---|---|---|
| KI-CDOWN-01 | グループ列はグループの基準で判定するが、1列目は全体の基準で表示するため、同じメンバーが全体列とグループ列で別の秒数になる（旧KI-SYNC-07） | 誤った出発指示の恐れ |
| KI-CDOWN-02 | 最大カウント秒が最後の出発カウントより小さいと、0側（最後に出発するメンバー）が警告なしで切り捨てられる（旧KI-SYNC-02、KI-SYNC-08） | 出発指示の漏れ |
| KI-CDOWN-03 | 1列目の値が0の行は、緑の強調が黄色の該当者の強調を上書きする（旧KI-SYNC-09） | 視認性 |
| KI-CDOWN-04 | `－`（全角ハイフンマイナス）や`—`は未所属とみなされず、グループ名として扱われる（旧KI-SYNC-10） | 意図しない列の追加 |
| KI-CDOWN-05 | 最大カウント秒に負数を入れると行が出ず、601以上も拒否しない（旧KI-SYNC-12） | 入力範囲が不明確 |
| KI-CDOWN-06 | 名簿の全行を削除して再表示すると、サンプル名簿に戻る（旧KI-SYNC-05） | 入力の消失 |
| KI-CDOWN-07 | コピーが失敗しても「コピーしました」と表示する（旧KI-SYNC-06） | 誤ったFeedback |
| KI-CDOWN-08 | 置き換える前の版のキー`kvkCountdownRosterState`の名簿と最大カウント秒を読まない（ADR 0031） | 保存した名簿が見えない |
| KI-CDOWN-09 | 「＋行を追加」だけでは保存せず、その行へ入力するまで再表示で消える | 入力の消失 |
| KI-CDOWN-10 | 速度ペットのボーナスを集結タイムライン計算で変えても、開いているページには再表示まで反映しない。古い値のまま1つのLvを変えると、9個すべてを保存し直すため、別のページで変えた値も上書きする | 古いボーナスで計算 |
| KI-CDOWN-11 | 名前があり到着秒数が空欄の行は、実際秒数が遅延秒数だけになって計算に入る。ほかの全員より実際秒数が小さければ最後に出発する人として表示され、最後の出発カウントも広がる。置き換える前の版とカウントアップ表（SYNC-004）は、到着秒数が数値でない行を除外していた | 誤った出発指示 |
| KI-CDOWN-12 | タブの「×」はフォーカスできない要素で、キーボードでタブを削除できない。キーボードでのタブの切り替えもない。COM-052を満たさない | キーボードで操作できない |
| KI-CDOWN-13 | タブを削除した後に「+」で追加すると、タブの数から名前を付けるため名前が重複する | 読み違い |

## 5. 未決事項

| ID | 問い |
|---|---|
| Q-CDOWN-01 | グループ列は、全体の基準とグループの基準のどちらで秒数を表すべきか（KI-CDOWN-01、旧Q-SYNC-02） |
| Q-CDOWN-02 | 名簿を全行削除した状態は保存し、サンプルへ戻さないべきか（旧Q-SYNC-03） |
| Q-CDOWN-03 | 最大カウント秒を超えるメンバーがいる場合、警告を出すか、上限を自動で広げるか（旧Q-SYNC-05） |
| Q-CDOWN-04 | 役割を出力や計算に使うか |
| Q-CDOWN-05 | 到着秒数が空欄の行を、カウントアップ表と同じく計算から除外するか（KI-CDOWN-11） |

## 6. 決定済みの事項

| 事項 | 決定 | 反映先 |

| 取り込み元の版への置き換え | 2026-11-03に利用者が、取り込み元の版で置き換え、GASとの連携を外すと決めた。外したのは、登録者の名前の候補、名前を入れたときに登録者の速度ペットLvを自動で入れる動作、登録者からの名簿の取り込み、相手の名前の候補と自動入力、共有用の表示とイベントの選択である。相手の名前と秒数は手で入力する。続けて、取り込んだ版の動作を正とし、仕様書を合わせると決めた | ADR 0031、CDOWN-001 |
