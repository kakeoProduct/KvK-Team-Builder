# 要件定義: 周期ウェーブタイマー

| 項目 | 内容 |
|---|---|
| 対象ファイル | `web/周期ウェーブタイマー.html` |
| 表示名 | 「周期ウェーブタイマー」 |
| 状態 | 稼働中 |
| 要件ID接頭辞 | `WAVE` |
| 現行仕様の確認日 | 2026-11-03（取り込み元の版へ置き換えた後のコードの読解と、`tests/web/`の検査による。自動取り込み、計測、時短のボタン（タッチでは効き、マウスでは効かなかった。KI-WAVE-30）、貼り付け欄を隠す操作、900px以下での貼り付け欄の非表示、横にはみ出さないことは、Chromium 130でDesktop幅（1280px）とMobile幅（390px）で確認（COM-053）。ADR 0031） |

## 1. 目的と利用場面

一定の周期で発生する予定（ウェーブ）ごとの経過時間を並べて表示する。スタートで1個目の予定が
始まり、周期ごとに次の予定を自動で追加し、一定時間を過ぎた予定を消す。あわせて、
[集結タイムライン計算](siege-timeline.md)の1周目の結果を、予定ごとに独立して進め、進行中の
パターン、まもなく発起する人、発起時刻を過ぎた人を表示する。

集結タイムライン計算で計算すると、周期、MAX、タイムラインを自動で受け取る。1つのページの中に
タブで複数のタイマーの設定を持てる。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 予定 | 周期ごとに追加される経過時間のカウンター。それぞれがタイムラインの1周を表す |
| 周期 | 予定を追加する間隔。設定欄で入力するか、集結タイムライン計算から受け取る |
| MAX | 予定の寿命の基準となる秒数 |
| 表示延長 | MAXを過ぎても予定を表示し続ける秒数。画面では「MAX＋◯秒まで表示」 |
| タイムライン | 集結タイムライン計算から受け取ったか貼り付けた、1周目のテキスト |
| 発起行 | タイムラインのうち、1人の発起を表す行 |
| 時短 | 発起に間に合わなかった人が、短い集結時間で後から発起すること |
| タブ | ページ内で切り替えるタイマー。設定、タイムライン、貼り付け欄の表示の有無をタブごとに持つ |

## 3. 機能要件

### 3.1 設定

| ID | 要件 |
|---|---|
| WAVE-001 | 「周期」（分、秒）、「MAX」（分、秒）、「MAX＋◯秒まで表示」（秒）を入力できる。既定値は周期10秒、MAX30秒、表示延長3秒 |
| WAVE-002 | 設定値はスタート時に確定する。周期とMAXは`分 × 60 + 秒`を整数で求め、1秒未満は1秒とする。表示延長は0秒未満を0秒とする |
| WAVE-003 | 計測中は、周期、MAX、表示延長の入力欄を編集できない |

### 3.2 予定の追加と削除

| ID | 要件 |
|---|---|
| WAVE-010 | スタート時刻を基準とし、k個目の予定を`スタート時刻 + (k - 1) × 周期`に追加する。1個目はスタートと同時に追加する |
| WAVE-011 | 予定の時刻は基準時刻からの絶対時刻で決め、ブラウザのタブの休止などで遅れても誤差を積み重ねない |
| WAVE-012 | 予定の経過時間が`MAX + 表示延長`に達したら、その予定を消す |
| WAVE-013 | 各予定の経過時間を`MM:SS.t`（0.1秒単位、切り捨て）でカウントアップ表示する。予定は古い順に「1個目」「2個目」…と並べる |
| WAVE-014 | 予定がない場合は「まだ予定がありません」と表示する |

### 3.3 操作

| ID | 要件 |
|---|---|
| WAVE-020 | 「スタート」で予定を初期化し、計測を始める。計測中の押下は無視する |
| WAVE-021 | 「ストップ」で予定の追加を止め、予定と進行表示の経過時間を停止時点で凍結表示する |
| WAVE-022 | ストップ後に「スタート」を押すと、予定を消して最初から計測する |
| WAVE-023 | 「リセット」で計測を止め、予定と進行表示を消す |

### 3.4 タイムラインの貼り付けと解析

| ID | 要件 |
|---|---|
| WAVE-030 | 貼り付け欄には表示中のタブのタイムラインを表示する。入力のたびにそのタブへ保存し、解析して表示を更新する。保存に成功したら「保存しました」、失敗したら「この環境では保存できません」を1.5秒間表示する |
| WAVE-031 | 前後の空白を除いた行が、行頭に`{分}分{秒}秒`（分1〜3桁、秒1〜2桁）または`{分}:{秒2桁}`（分1〜3桁）を持ち、`→`を含み、`→`より後に`①`〜`⑳`のいずれかを含む場合に、その行を発起行とする。行頭の時刻を発起時刻、`→`より後の最初の`①`〜`⑳`をパターンの記号、記号の直後から`（`または`(`の前までを前後の空白を除いて名前とする。`（{分}分集結）`（括弧は全角、半角のどちらでもよく、分は1〜3桁）があれば、その分を集結時間とする。それ以外の行（見出し、空行、`周期：`の行など）は読まない |
| WAVE-032 | 同じ記号の発起行をまとめて1つのパターンとする。パターンの見出しは記号に、名前を出現順に重複なく`+`で連結したものとし、パターンの最後の発起は発起時刻の最大値とする |
| WAVE-035 | 画面幅が900px以下の場合は貼り付け欄を表示しない。保存済みのタイムラインの解析と表示は続ける |
| WAVE-036 | 貼り付け欄の文字サイズを16pxから8pxまでの範囲で、欄に収まるよう自動で調整する |
| WAVE-037 | 「貼り付け欄を隠す」で貼り付け欄を隠してタイマーを横に広げ、「貼り付け欄を表示」で戻す。表示の有無はタブごとに保存する |

### 3.5 進行表示

| ID | 要件 |
|---|---|
| WAVE-043 | 発起行が1つもない場合は、1個目の予定のカードに「タイムラインのテキストが貼り付けられていません」と表示する |
| WAVE-044 | 各予定は、追加された時刻をタイムラインの0秒とし、それぞれ独立にタイムラインを進める。周回の計算はしない |
| WAVE-045 | 1個目の予定のカードの右側に、その予定の経過時間がパターンの最後の発起（WAVE-032）より前のパターンの見出しを並べる。見出しは、タイムラインに記号が最初に現れた順に並べる |
| WAVE-046 | 各予定について、発起まで0秒以上60秒以内の発起行を、残り秒数（四捨五入）ごとにまとめ、その予定のカードの上に「⏱ {秒}秒後：{記号}{名前}、…」と残りの短い順に表示する。まとまりの中の名前は、タイムラインの元の発起時刻の順とする |
| WAVE-047 | 各予定について、発起時刻を過ぎて0秒以上30秒以内の発起行を、過ぎた秒数（四捨五入）ごとにまとめ、その予定のカードの下に「⚠ {秒}秒前に発起予定だった：{記号}{名前}、…」と表示する。WAVE-046もWAVE-047も0秒を含むため、発起時刻ちょうどには同じ人が両方に出る。まとまりは、過ぎた秒数の短い順に並べる |
| WAVE-048 | WAVE-047の各まとまりに、集結時間の候補（1分、3分、5分）のうち元の集結時間より短い最大のものを使う「{分}分集結で出す（{秒}秒後）」のボタンを置く。秒は、元の着弾に間に合う新しい発起時刻（`発起時刻 + (元の集結時間 - 候補) × 60`）までの残り秒数（四捨五入）とする。元の集結時間と発起時刻は、まとまりの最初の発起行のものを使う。元の集結時間が読めないか、短い候補がなければボタンを置かない |
| WAVE-049 | WAVE-048のボタンを押すと、その予定のまとまりの人それぞれを、ボタンの集結時間で発起するものとして扱う。各人の新しい発起時刻は`その人の発起時刻 + (その人の元の集結時間 - ボタンの集結時間) × 60`とし、WAVE-047の表示から外し、WAVE-046では新しい発起時刻で表示する。この扱いは予定の番号、記号、名前で覚え、その番号の予定が消えて表示を描き直すときに捨てる |

### 3.6 タブ

| ID | 要件 |
|---|---|
| WAVE-060 | ページ内のタブで複数のタイマーの設定を切り替えられる。各タブは設定、タイムライン、貼り付け欄の表示の有無を独立に持つ。計測するのは表示中のタブだけとする |
| WAVE-063 | 「+」で、設定が既定値でタイムラインが空の新しいタブを末尾へ追加して表示する。名前は「タイマー{追加前のタブの数 + 1}」とする |
| WAVE-064 | タブの名前は、タブの上の欄で直接変更できる。別のタブの名前の欄をクリックすると、そのタブを表示する（WAVE-067） |
| WAVE-065 | タブの「×」で、そのタブと保存した内容を削除できる。削除の前に確認を出し、取り消した場合は何も変えない。タブが1つだけの場合は「×」を出さない。表示中のタブを削除した後は、先頭のタブを表示する |
| WAVE-067 | 計測中またはストップ後に別のタブへ切り替える場合（タブの追加と、表示中のタブの削除による切り替えを含む）は確認を出し、取り消した場合は切り替えない。切り替えると計測を終えて予定を消す |

### 3.7 集結タイムライン計算からの自動取り込み

| ID | 要件 |
|---|---|
| WAVE-080 | ページを開いたときと、別のブラウザのタブで集結タイムライン計算の結果（SIEGE-045）が保存されたときに、その結果を表示中のタブへ取り込む。計測中は取り込まない。同じ結果（`savedAt`が同じ）は、ページを開いている間に2度取り込まない |
| WAVE-081 | 取り込みでは、`periodSec`が正の数なら周期へ、`maxSec`が正の数ならMAXへ、分は`floor(秒 ÷ 60)`、秒は`秒 ÷ 60`の余りを四捨五入した値として入れ、`rawText`が空でなければ貼り付け欄を置き換える。設定とタイムラインを保存し、解析して表示を更新し、「集結タイムライン計算の結果を自動取得しました」を2.5秒間表示する |
| WAVE-082 | 集結タイムライン計算の保存データは読むだけで、書き換えない |

### 3.8 保存

| ID | 要件 |
|---|---|
| WAVE-050 | タブの一覧（`id`と名前）をキー`waveTimerTabs`へ、最後に表示していたタブの`id`をキー`waveTimerCurrentTab`へ、タブの追加、削除、切り替え、名前の変更のたびに保存し、次回表示時に復元する。計測の状態は保存せず、ページを開き直したときは停止している |
| WAVE-051 | タブごとに、設定（`{periodMin, periodSec, maxMin, maxSec, extraDisplaySec}`）を設定の入力のたびに`waveTimerSettings_{id}`へ、タイムラインを貼り付け欄のテキストのまま`waveTimerPastedTimeline_{id}`へ、貼り付け欄を隠しているかを`"1"`または`"0"`で`waveTimerSideHidden_{id}`へ保存する |
| WAVE-052 | 最初のタブ（`id`が`default`、名前「タイマー1」）は、接尾辞のないキー`waveTimerSettings`、`waveTimerPastedTimeline`、`waveTimerSideHidden`を使い、タブを加える前の保存データをそのまま引き継ぐ。`waveTimerTabs`が空でない配列でなければ、このタブだけを表示する |

```text
waveTimerTabs: [{id, title}]
```

## 4. 既知の不具合と現行実装との差異

| ID | 内容 | 影響 |
|---|---|---|
| KI-WAVE-01 | 副題は「各予定はMAX秒で消えます」だが、実際は`MAX + 表示延長`で消える。MAXに達した時点で表示が変わらない | MAXの到達が分からない |
| KI-WAVE-04 | まだ始まっていないパターンと進行中のパターンを区別せずに表示する | 読み違い |
| KI-WAVE-05 | 予定のカードがない間は、パターンの進行が表示されない。パターンの見出しは1個目の予定にだけ出すため、前の予定が`MAX + 表示延長`まで残る間は、進行中の2個目の予定の見出しが出ない | 情報の欠落 |
| KI-WAVE-06 | 予定の「N個目」は表示中の並び順であり、古い予定が消えると番号が詰まる | 何番目のウェーブか分からない |
| KI-WAVE-07 | 一時停止と再開ができない。ストップ後のスタートは最初からになる | 中断後に続けられない |
| KI-WAVE-11 | パターンの見出し、まもなく発起する人と発起できなかった人の名前を、`innerHTML`へエスケープせずに挿入する | 表示崩れ、安全性 |
| KI-WAVE-12 | テキストを貼り付けても解析に失敗すると「貼り付けられていません」と表示し、原因が分からない | 誤ったFeedback |
| KI-WAVE-15 | タイムラインの`周期：`の行を読まない。貼り付けだけでは周期とMAXが変わらず、手で入力する必要がある。置き換える前の版も周期の入力へは反映せず、`周期：`の行は進行表示の1周としてだけ使っていた（旧WAVE-033） | 誤った周期で計測 |
| KI-WAVE-16 | ページを開くたびに、集結タイムライン計算の最新の結果を表示中のタブへ取り込み、そのタブで手で入れた設定と貼り付けたタイムラインを上書きする | 入力の消失 |
| KI-WAVE-17 | 計測中に集結タイムライン計算で計算した結果は取り込まず、ストップ後も、次の計算かページの開き直しまで取り込まない | 古いタイムラインで計測 |
| KI-WAVE-18 | タブを切り替えると計測を終える。置き換える前の版では、表示していないタブも計測を続けていた（旧WAVE-061。ADR 0031） | 複数のタイマーを同時に使えない |
| KI-WAVE-19 | 置き換える前の版のタブの保存データ（`waveTimerTabs`の旧形式）を読まず、タブを1つに戻す。タブを操作すると新しい形式で上書きする（ADR 0031） | 保存したタブが見えない |
| KI-WAVE-20 | タブを削除した後に追加すると、タブの数から名前を付けるため名前が重複する | 読み違い |
| KI-WAVE-21 | 集結タイムライン計算の結果は、周期ウェーブタイマーのどのタブ向けのものかを区別せず、受け取った時点で表示中のタブへ取り込む | 別の編成のタイムラインを使うおそれ |
| KI-WAVE-22 | 計測中にタブを追加するか表示中のタブを削除し、WAVE-067の確認を取り消すと、追加したタブは表示されないまま残り、削除したタブは一覧から消えたまま表示され続ける | 状態の不一致 |
| KI-WAVE-23 | 時短の扱い（WAVE-049）は、ストップ、リセット、タブの切り替えでは捨てない。再スタートで予定の番号が1に戻るため、前の計測で時短を選んだ人が、新しい1個目でも時短で発起するものとして表示されることがある | 誤った発起の指示 |
| KI-WAVE-24 | 経過時間を`MAX - 残り`から求めるため、0.1秒のちょうど境目で浮動小数の誤差により0.1秒少なく表示することがある（例: 12.9秒を`00:12.8`） | わずかな表示のずれ |
| KI-WAVE-25 | 集結時間の違う人が同じ秒にまとまると、ボタン（WAVE-048）はまとまりの最初の人の集結時間から作る。元の集結時間がボタン以下の人は、新しい発起時刻が元の時刻以前（既に過ぎた時刻）になり、WAVE-046にもWAVE-047にも出なくなる。集結時間が読めない人（WAVE-031）も、発起時刻が変わらないまま両方の表示から外れる | 発起の指示の消失 |
| KI-WAVE-26 | 取り込んだ周期やMAXが小数で、秒の余りが59.5以上だと、秒の欄が60になる（例: 59.6秒を「0分60秒」）。周期とMAXが小数になるのは、集結タイムライン計算のフェーズ間隔、パターン間バッファ、採用オフの行軍秒数に小数を入れたとき | 読み違い |
| KI-WAVE-27 | `①`〜`⑳`を含まない行は発起行として読まない。集結タイムライン計算の21個目以降のパターン（`(21)`）と、名前を変えて記号を含まなくなったパターンの人は、ほかのパターンが読めれば知らせなしにタイムラインから消える。同じ記号のパターンが2つあると1つにまとめる（KI-SIEGE-08） | 発起の指示の欠落 |
| KI-WAVE-28 | 予定ごとに独立して進むため、次の予定の0〜60秒の発起は、その予定が追加されるまで予告しない。各周の最初の発起（タイムラインの0秒）は予告なしにWAVE-047と時短のボタンに出る。置き換える前の「次の周で最も早く始まるパターンまでの残り時間」（旧WAVE-042）はなくなった | 先頭の発起者への予告がない |
| KI-WAVE-29 | タブの「×」はフォーカスできない要素で、キーボードでタブを削除できない。キーボードでのタブの切り替え（旧WAVE-066）もない。COM-052を満たさない | キーボードで操作できない |
| KI-WAVE-30 | 計測中は時短のボタンを毎フレーム作り直すため、マウスで押してもボタンが効かないことがある。2026-11-03にChromium 130のDesktop幅で、押してから離すまで120ミリ秒の操作で効かなかった。Mobile幅のタッチでは効いた | 時短を選べない |

## 7. 作成者の仮定

| 要件 | 仮定 |
|---|---|
| WAVE-048 | 時短の候補（1分、3分、5分）は、取り込み元の値をそのまま使う |
