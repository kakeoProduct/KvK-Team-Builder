# 要件定義: 集結タイムライン計算

| 項目 | 内容 |
|---|---|
| 対象ファイル | `web/攻城タイムライン計算.html` |
| 表示名 | 「集結タイムライン計算」 |
| 状態 | 稼働中 |
| 要件ID接頭辞 | `SIEGE` |
| 現行仕様の確認日 | 2026-10-17（コードの読解による。ブラウザでの動作確認は未実施） |

## 1. 目的と利用場面

「メイン合わせ集結」作戦で、削り、メイン、増援の集結を階段状に着弾させるタイムラインを
自動計算する。削り担当は複数のパターンに分けて設定でき、メインと増援は全パターンで共通に
参加する。1周目の結果をDiscordへ貼り付けて共有し、[周期ウェーブタイマー](wave-timer.md)へ
貼り付けて繰り返し実行する。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 役割 | 「メイン」「増援」「削り」のいずれか |
| パターン | 一度に着弾させる削りメンバーの組み合わせ。①②③…と名付ける |
| 発起 | 集結を開始する時刻 |
| 着弾 | 集結が目標へ到着する時刻 |
| 帰還 | 部隊が戻り、次の集結に使える状態へ近づく時刻 |
| 周期 | 同じパターンが次の周で再び着弾するまでの秒数 |

時刻はすべて、計算の起点を0秒とする相対時刻で表す。

## 3. 機能要件

### 3.1 入力

| ID | 要件 |
|---|---|
| SIEGE-001 | 共通設定として「削りの集結時間（分）」（既定5）、「メイン／増援の集結時間（分）」（既定3）、「フェーズ間隔（秒）」（既定1）、「パターン間バッファ（秒）」（既定30）を入力できる |
| SIEGE-002 | メンバーごとに役割、「ラベル／名前」、「行軍秒数」を入力でき、「+ メンバー追加」で行を追加、「削除」で行を削除できる。追加した行の既定は役割「削り」、ラベル空、行軍0 |
| SIEGE-003 | パターンごとに名前と、役割が削りのメンバーをチェックボックスで選べる。「+ パターン追加」で`①`〜`⑳`の順に名付けて追加し、21個目以降は`(21)`の形式とする |
| SIEGE-004 | メンバーを削除した場合は、全パターンの選択からも外す |
| SIEGE-005 | 削りのメンバーがいない場合は「削り役割のメンバーがいません」、パターンがない場合は「パターンがありません」と表示する |
| SIEGE-006 | 初回表示時（保存データがないとき）は、メイン1人、増援1人、削りA〜F、パターン①（A、B、C）、②（D）、③（E、F）のサンプルを表示する |

### 3.2 計算規則

| ID | 要件 |
|---|---|
| SIEGE-010 | 集結時間（分）は60倍して秒へ換算する |
| SIEGE-011 | 2周分の「周×パターン」を計算し、各メンバーが次に使える時刻（以下、使用可能時刻）を0秒から更新する |
| SIEGE-012 | パターンの削りの最小着弾時刻Tは、0、各削りの`使用可能時刻 + 削りの集結時間 + 行軍`、各メインの`使用可能時刻 + メインの集結時間 + 行軍 - フェーズ間隔`、各増援の`使用可能時刻 + メインの集結時間 + 行軍 - 2 × フェーズ間隔`の最大値とする |
| SIEGE-013 | 未確定のパターンのうちTが最小のものから1件ずつ確定する。同じTの場合は、周、パターン定義順で先のものを優先する |
| SIEGE-014 | 着弾は削りがT、メインが`T + フェーズ間隔`、増援が`T + 2 × フェーズ間隔`とする |
| SIEGE-015 | 発起は`着弾 - 集結時間 - 行軍`、帰還は`着弾 + 行軍`とする |
| SIEGE-016 | 確定したメンバーの使用可能時刻を`帰還 + パターン間バッファ`へ更新する |
| SIEGE-017 | 周期は、先頭パターンの2周目のTから1周目のTを引いた値とする |
| SIEGE-018 | メインと増援は、削りの有無にかかわらず全パターンに参加する |

### 3.3 出力

| ID | 要件 |
|---|---|
| SIEGE-020 | 「計算結果（1周目）」に1周目の全パターンをパターン定義順に出し、末尾へ`周期：{周期}`の行を付ける。この行は周期ウェーブタイマーが1周の長さとして読むため、必ず出力する |
| SIEGE-021 | 「参考：2周分の計算結果」に`【1周目】`と`【2周目】`の全パターンと周期を確認用として出す。コピーの対象にしない |
| SIEGE-022 | 時刻は四捨五入した秒を`{分}分{秒2桁}秒`で表し、60分以上も時間へ繰り上げない |
| SIEGE-023 | 集結時間は秒が0なら`{分}分`、それ以外は`{分}分{秒}秒`で表す |
| SIEGE-024 | パターンごとの書式は次のとおりとし、各行は削り、メイン、増援の順に並べる。パターンの間は空行で区切る |

```text
{パターン名}{削りのラベルを+で連結}→メイン→増援
{発起} → {ラベル}（{集結時間}集結）※行軍{行軍秒数}秒（{着弾}着、{帰還}帰還）
```

この出力書式は運用者の指示で確定済みであり、`mm:ss`形式などへ変更しない。

### 3.4 操作

| ID | 要件 |
|---|---|
| SIEGE-030 | 「タイムラインを計算」で計算し、結果カードを表示する |
| SIEGE-031 | 「Discord用にコピー」で1周目の出力をクリップボードへコピーし、1.5秒間「コピーしました」と表示する |
| SIEGE-032 | パターンが0件の場合は、出力欄に「パターンが設定されていません。」と表示する |

### 3.5 保存

| ID | 要件 |
|---|---|
| SIEGE-040 | メンバー、パターン、共通設定を変更のたびにlocalStorageのキー`siegeCalcState`へ保存し、次回表示時に復元する。計算結果は保存しない |
| SIEGE-041 | 保存形式は`{memberSeq, patternSeq, members: [{id, role, label, march}], patterns: [{id, name, kezuriIds}], settings: {kezuriRallyMin, mainRallyMin, phaseGap, buffer}}`とする |

## 4. 既知の不具合と現行実装との差異

| ID | 内容 | 影響 |
|---|---|---|
| KI-SIEGE-01 | 削りのメンバーを他の役割へ変えても、パターンの選択に残る。メインへ変えたメンバーが削りとしても計算され、画面からは外せない | 誤ったタイムライン |
| KI-SIEGE-02 | パターンを0件にして計算すると、前回の参考結果が消えずに残る | 古い結果の誤用 |
| KI-SIEGE-03 | 「パターン間バッファ」は実際にはメンバーごとの帰還後の待ち時間として使われ、名称と挙動が一致しない | 設定の誤解 |
| KI-SIEGE-04 | 周期を先頭パターンだけで求めており、2周目で定常状態になっていない場合に周期がずれる可能性がある | 周期ウェーブタイマーのずれ |
| KI-SIEGE-05 | 出力はパターン定義順であり、確定した時刻の順と一致しない場合がある | 読み違い |
| KI-SIEGE-06 | 集結時間（分）は小数を切り捨てる。負数を拒否せず、発起時刻が負になると時刻表示が崩れる | 入力範囲が不明確 |
| KI-SIEGE-07 | 小数の行軍秒数で、行軍の表示に浮動小数の誤差が出る可能性がある | 表示崩れ |
| KI-SIEGE-08 | パターンの削除後に追加すると、件数から名前を付けるため名前が重複する | 読み違い |
| KI-SIEGE-09 | ラベルが空のメンバーは、画面では「(無名)」だが出力では空文字になる | 読み違い |
| KI-SIEGE-10 | 全メンバーを削除して再読み込みすると、サンプルと既定の設定値で上書きされる | 入力の消失 |
| KI-SIEGE-11 | コピーに失敗しても通知しない | 誤ったFeedback |
| KI-SIEGE-12 | メインまたは増援が0人でも見出しは「→メイン→増援」のままになる | 読み違い |
| KI-SIEGE-13 | ファイル名の「攻城タイムライン計算」と表示名の「集結タイムライン計算」が一致しない | 保守時の混乱 |
