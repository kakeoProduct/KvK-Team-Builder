## 1. 目的と利用場面

「メイン合わせ集結」作戦で、削り、メイン、増援の集結を階段状に着弾させるタイムラインを
自動計算する。削り担当は複数のパターンに分けて設定でき、メインと増援は全パターンで共通に
参加する。1周目の結果をDiscordへ貼り付けて共有し、[周期ウェーブタイマー](wave-timer.md)で
読み込むか貼り付けて、1周目を周期ごとに繰り返し実行する。

1つのページの中にタブで複数の計算機を持ち、編成ごとに入力と計算結果を分けて残せる。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 役割 | 「メイン」「増援」「削り」のいずれか |
| パターン | 一度に着弾させる削りメンバーの組み合わせ。①②③…と名付ける |
| 発起 | 集結を開始する時刻 |
| 着弾 | 集結が目標へ到着する時刻 |
| 帰還 | 部隊が戻り、次の集結に使える状態へ近づく時刻 |
| 周期 | 1周目を繰り返すときの、ある周から次の周までの秒数。全パターンで共通の1つの値 |
| タブ | ページ内で切り替える計算機。共通設定、メンバー、パターン、計算結果をタブごとに持つ |

時刻はすべて、計算の起点を0秒とする相対時刻で表す。

## 3. 機能要件

### 3.1 入力

| ID | 要件 |
|---|---|
| SIEGE-001 | 共通設定として「削りの集結時間（分）」（既定5）、「メイン／増援の集結時間（分）」（既定3）、「フェーズ間隔（秒）」（既定1）、「パターン間バッファ（秒）」（既定30）を入力できる |
| SIEGE-002 | メンバーごとに役割、「ラベル／名前」、「行軍秒数」を入力でき、「+ メンバー追加」で行を追加、「削除」で行を削除できる。追加した行の既定は役割「削り」、ラベル空、行軍0 |
| SIEGE-003 | パターンごとに名前と、役割が削りのメンバーをチェックボックスで選べる。「+ パターン追加」で`①`〜`⑳`の順に名付けて追加し、21個目以降は`(21)`の形式とする |
| SIEGE-004 | メンバーを削除した場合は、全パターンの選択からも外す |
| SIEGE-005 | 削りのメンバーがいない場合は「削り役割のメンバーがいません」、パターンがない場合は「パターンがありません」と表示する |
| SIEGE-006 | SIEGE-042で移す内容がない初回表示時は、メイン1人、増援1人、削りA〜F、パターン①（A、B、C）、②（D）、③（E、F）のサンプルと、共通設定の既定値を入れたタブ「計算1」を1つ作る |

### 3.2 計算規則

| ID | 要件 |
|---|---|
| SIEGE-010 | 集結時間（分）は60倍して秒へ換算する |
| SIEGE-011 | 1周目の全パターンを計算し、各メンバーが次に使える時刻（以下、使用可能時刻）を0秒から更新する。2周目はSIEGE-021のとおり1周目から求める |
| SIEGE-012 | パターンの削りの最小着弾時刻Tは、0、各削りの`使用可能時刻 + 削りの集結時間 + 行軍`、各メインの`使用可能時刻 + メインの集結時間 + 行軍 - フェーズ間隔`、各増援の`使用可能時刻 + メインの集結時間 + 行軍 - 2 × フェーズ間隔`の最大値とする |
| SIEGE-013 | 1周目のパターンを定義順（①②③…）に1件ずつ確定する。各パターンのTは、その時点の使用可能時刻からSIEGE-012で求める |
| SIEGE-014 | 着弾は削りがT、メインが`T + フェーズ間隔`、増援が`T + 2 × フェーズ間隔`とする |
| SIEGE-015 | 発起は`着弾 - 集結時間 - 行軍`、帰還は`着弾 + 行軍`とする |
| SIEGE-016 | 確定したメンバーの使用可能時刻を`帰還 + パターン間バッファ`へ更新する |
| SIEGE-017 | 周期Pは、1周目の確定結果から求める次の2つの最大値とする。① メンバーごとの`max(帰還 + パターン間バッファ) - min(発起)`。② `最後のパターンのT - 先頭のパターンのT`。周期は周ごとに変えない |
| SIEGE-018 | メインと増援は、削りの有無にかかわらず全パターンに参加する。メインは1人以上必要とし（SIEGE-033）、増援は0人でもよい |

#### 確定順と周期の考え方

- **定義順に確定する理由:** 以前は、未確定のパターンのうちTが最小のものから確定していた。
  この方法では、1周目と2周目でパターンの順番が変わる（たとえば1周目が②①③、2周目が①②③）。
  周期ウェーブタイマーは1周目を周期ごとに繰り返すため、順番が変わると待ち時間を破る指示になる。
- **周期を最小値で求める理由:** 定義順にしても、削りの戻りに必要な間隔
  （`2 × 行軍 + 削りの集結時間 + パターン間バッファ`）がパターンごとに違うと、2周目を計算し直した
  ときのパターンの間隔がそろわない。このため、1周目をPずつずらして繰り返しても、全員が
  `帰還 + パターン間バッファ`以降に次の集結を発起でき、パターンの順番も変わらない最小の値を周期とする。
- **限界:** 1周目の時刻の組み方は変えないため、時刻の組み方まで変えれば周期を短くできる入力がまれにある。
  決定的な乱数で作った1000件の入力では、1件だけ真の最小周期より65秒長かった（2026-10-25のGit管理外の
  事前検証による。真の最小周期との比較は`tests/web/`の検査では行っていない）。
  入力は整数秒を前提とする。小数の入力では、周期を四捨五入して表示する（SIEGE-022）ため、表示した周期で
  繰り返すと待ち時間を1秒未満だけ破ることがある（KI-SIEGE-06、KI-SIEGE-07と同じく範囲外）。

#### 計算結果が満たす性質

`tests/web/`の検査は、出力テキストと入力だけから次の性質を確かめる。固定の例と、決定的な乱数で作った
1000件の入力（メイン1〜2人、増援0〜2人、削り1〜8人、パターン1〜5件）で、違反が0件であることを求める。
削りを選んでいないパターン（SIEGE-003）を含む入力は、固定の例と、別の乱数で作った100件で確かめる。
削りを選んでいないパターンのTは、メインの着弾からフェーズ間隔を引いた値とする（SIEGE-014）。

| ID | 性質 | 根拠の要件 |
|---|---|---|
| C1 | 発起が0秒より前にならない | SIEGE-012 |
| C2 | 2周分を通して、同じ人の次の発起が、前回の`帰還 + パターン間バッファ`以降になる | SIEGE-016 |
| C3 | 削りは同時にTで着弾し、メインは`T + フェーズ間隔`、増援は`T + 2 × フェーズ間隔`で着弾する。発起と帰還はSIEGE-015の式に従う | SIEGE-014、SIEGE-015 |
| C4 | 1周目と2周目でパターンの着弾の順番が同じ | SIEGE-013、SIEGE-021 |
| C5 | どのパターンも、2周目と1周目の着弾の差が表示した周期と一致する | SIEGE-017、SIEGE-021 |
| C6 | 1周目を周期ずつずらして繰り返しても、C2を守れる | SIEGE-017 |
| C7 | 周期は、1周目の時刻を変えない範囲で、C6とパターンの順番を守る最小の値である | SIEGE-017 |
| C8 | 「計算結果（1周目）」は、参考の1周目と同じ本文に`周期：`の行を付けたものである | SIEGE-020、SIEGE-021 |
| C9 | 入力どおりのパターン数で、各パターンの見出しと行（削り、メイン、増援の順）が入力と一致する | SIEGE-018、SIEGE-024 |
| C10 | 1周目の各パターンのTは、それより前のパターンの帰還とパターン間バッファから求めた使用可能時刻で、SIEGE-012の最大値に等しい（着弾を必要以上に遅らせない） | SIEGE-012、SIEGE-013、SIEGE-016 |

### 3.3 出力

| ID | 要件 |
|---|---|
| SIEGE-020 | 「計算結果（1周目）」に1周目の全パターンをパターン定義順に出し、末尾へ`周期：{周期}`の行を付ける。この行は周期ウェーブタイマーが1周の長さとして読むため、必ず出力する。パターン定義順は確定順（SIEGE-013）と一致する |
| SIEGE-021 | 「参考：2周分の計算結果」に`【1周目】`と`【2周目】`の全パターンと周期を確認用として出す。2周目は、1周目の全時刻（発起、着弾、帰還）へ周期を足したものとする。コピーの対象にしない |
| SIEGE-022 | 時刻は四捨五入した秒を`{分}分{秒2桁}秒`で表し、60分以上も時間へ繰り上げない |
| SIEGE-023 | 集結時間は秒が0なら`{分}分`、それ以外は`{分}分{秒}秒`で表す |
| SIEGE-024 | パターンごとの書式は次のとおりとし、各行は削り、メイン、増援の順に並べる。パターンの間は空行で区切る |

```text
{パターン名}{削りのラベルを+で連結}→メイン→増援
{発起} → {ラベル}（{集結時間}集結）※行軍{行軍秒数}秒（{着弾}着、{帰還}帰還）
```

この出力書式は運用者の指示で確定済みであり、`mm:ss`形式などへ変更しない。

### 3.4 操作

| ID | 要件 |
|---|---|
| SIEGE-030 | 「タイムラインを計算」で表示中のタブを計算し、結果カードを表示する |
| SIEGE-031 | 「Discord用にコピー」で1周目の出力をクリップボードへコピーし、1.5秒間「コピーしました」と表示する |
| SIEGE-032 | パターンが0件の場合は、時刻を計算せずに出力欄へ「パターンが設定されていません。」と表示する |
| SIEGE-033 | パターンが1件以上あり、役割がメインのメンバーがいない場合は、時刻を計算せずに出力欄へ「メイン役割のメンバーがいません」と表示する |
| SIEGE-034 | SIEGE-032、SIEGE-033のメッセージを出すときは、前回の「参考：2周分の計算結果」を消さずに表示し続け、保存する。再表示でも残す。残した参考結果の入力と今の入力が違う間は、SIEGE-043の注意を表示する |

### 3.5 タブ

| ID | 要件 |
|---|---|
| SIEGE-050 | ページ内のタブで複数の計算機を切り替えられる。各タブは共通設定、メンバー、パターン、計算結果をすべて独立に持ち、あるタブの変更と計算は他のタブへ影響しない |
| SIEGE-051 | 「+ タブ追加」で新しいタブを末尾へ追加して表示する。新しいタブは、表示中のタブのメンバー、パターン、共通設定を複製して始め、計算結果は写さない。名前は追加した順の通し番号で「計算1」「計算2」…とし、タブを削除しても番号を再利用しない |
| SIEGE-052 | 表示中のタブの名前を「タブ名」の欄で変更できる。名前を空にした場合は、そのタブの既定の名前（「計算{番号}」）を表示する |
| SIEGE-053 | 「このタブを削除」で表示中のタブを削除できる。削除の前に確認を出し、取り消した場合は何も変えない。タブが1つだけの場合は削除できない。削除後は、削除したタブの右隣、なければ左隣のタブを表示する |
| SIEGE-054 | タブの切り替えをキーボードで行える。タブの並びにFocusがあるとき、左右の矢印キーで前後のタブ、HomeとEndで先頭と末尾のタブへ移って表示する。末尾で右の矢印キーを押すと先頭へ、先頭で左の矢印キーを押すと末尾へ移る。Focusを表示する |

### 3.6 保存

| ID | 要件 |
|---|---|
| SIEGE-040 | すべてのタブ（名前、メンバー、パターン、共通設定、最新の計算結果）と、最後に表示していたタブを、変更と計算のたびにlocalStorageのキー`siegeCalcTabs`へ保存し、次回表示時に復元する。表示中のタブに保存済みの計算結果があれば、結果カードも表示する |
| SIEGE-041 | 保存形式は次のとおりとする。タブの`id`は、これまでに作ったタブ（削除したタブと、SIEGE-042で作り直す前の保存データにあったタブを含む）と重ならない値とし、開き直しても保存した値を保つ（周期ウェーブタイマーが計算元を見分けるため）。`result`は未計算なら`null`とする。`revision`はタブごとに計算（「タイムラインを計算」を押すこと。SIEGE-032、SIEGE-033のメッセージを出す場合を含む）のたびに1ずつ増える版番号、`ok`は周期ウェーブタイマーが読み込める結果か（SIEGE-032、SIEGE-033のメッセージのときは`false`）、`output`は「計算結果（1周目）」の本文、`reference`は「参考：2周分の計算結果」の本文（表示していなければ`null`）、`inputKey`は参考結果を計算した入力（メンバー、パターン、共通設定）を表す文字列、または`null`とする。SIEGE-032、SIEGE-033のメッセージを出したときは、残した参考結果があれば前回の`inputKey`を引き継ぎ、なければ`null`とする |
| SIEGE-042 | `siegeCalcTabs`がないか、読めない（空、または壊れている）場合に、旧キー`siegeCalcState`があれば、その内容（メンバー、パターン、共通設定）をメンバーの人数によらず最初のタブ「計算1」へ移す。旧キーもなければSIEGE-006のタブを作る。旧キーは読むだけで、書き換えも削除もしない |
| SIEGE-043 | 計算した後にメンバー、パターン、共通設定を変え、今の入力が`inputKey`（SIEGE-041）の表す入力と違う間は、「計算結果（1周目）」のカードに「⚠ 入力が変更されています。計算し直してください」と表示する。最後の計算でSIEGE-032、SIEGE-033のメッセージを出した場合（`ok`が`false`）は、残した参考結果（SIEGE-034）の入力と比べ、違う間は「⚠ 参考：2周分の計算結果は、変更前の入力で計算したものです」と表示する。`inputKey`が`null`のときは表示しない。保存した計算結果は消さず、周期ウェーブタイマーは最後に計算した結果を読み込む。再表示でも同じ表示をする |
| SIEGE-044 | 同じページを別のブラウザのタブで開いていて、そちらで`siegeCalcTabs`が保存されたら、その保存データで表示を読み直す。表示中のタブが残っていればそのタブを表示し続け、なければ保存データの最後に表示していたタブを表示する。読めない保存データは無視する。別のページへ移って戻ったとき（ブラウザがページを復元したとき）も読み直す。これにより、後から保存した側が、もう一方のブラウザのタブで加えたタブと計算結果を消さない |

```text
{version: 1, tabSeq, activeTabId,
 tabs: [{id, seq, name, memberSeq, patternSeq,
         members: [{id, role, label, march}],
         patterns: [{id, name, kezuriIds}],
         settings: {kezuriRallyMin, mainRallyMin, phaseGap, buffer},
         result: null | {revision, ok, output, reference: null | 文字列, inputKey: null | 文字列}}]}
```

旧キー`siegeCalcState`の形式は
`{memberSeq, patternSeq, members: [{id, role, label, march}], patterns: [{id, name, kezuriIds}], settings: {kezuriRallyMin, mainRallyMin, phaseGap, buffer}}`
である。

## 4. 既知の不具合と現行実装との差異
