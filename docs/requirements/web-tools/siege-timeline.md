# 要件定義: 集結タイムライン計算

| 項目 | 内容 |
|---|---|
| 対象ファイル | `web/攻城タイムライン計算.html`、`web/pet-bonus.js`（速度ペットの共通部品） |
| 表示名 | 「集結タイムライン計算」 |
| 状態 | 稼働中 |
| 要件ID接頭辞 | `SIEGE` |
| 現行仕様の確認日 | 2026-11-03（取り込み元の版へ置き換えた後のコードの読解と、`tests/web/`の検査による。共通部品の読み込み、計算、周期ウェーブタイマーへの受け渡し、速度ペットの編集欄、横にはみ出さないことは、Chromium 130でDesktop幅（1280px）とMobile幅（390px）で確認（COM-053）。ADR 0031） |

## 1. 目的と利用場面

「メイン合わせ集結」作戦で、削り、メイン、増援の集結を階段状に着弾させるタイムラインを
自動計算する。削り担当と増援はパターンごとに選び、メインは全パターンで共通に参加する。
1周目の結果をDiscordへ貼り付けて共有し、[周期ウェーブタイマー](wave-timer.md)へ自動で渡して、
1周目を周期ごとに繰り返し実行する。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 役割 | 「メイン」「増援」「削り」のいずれか |
| パターン | 一度に着弾させる削りと増援の組み合わせ。①②③…と名付ける |
| 発起 | 集結を開始する時刻 |
| 着弾 | 集結が目標へ到着する時刻 |
| 帰還 | 部隊が戻り、次の集結に使える状態へ近づく時刻 |
| 周期 | 1周目を繰り返すときの、ある周から次の周までの秒数 |
| 速度ペット | 行軍を速くするペット。レベル（Lv1〜Lv8）ごとのボーナス（%）で行軍秒数を縮める |
| 採用 | 速度ペットありの行軍秒数を計算に使うか |

時刻はすべて、計算の起点を0秒とする相対時刻で表す。

## 3. 機能要件

### 3.1 入力

| ID | 要件 |
|---|---|
| SIEGE-001 | 共通設定として「削りの集結時間（分）」（既定5）、「メイン／増援の集結時間（分）」（既定3）、「フェーズ間隔（秒）」（既定1）、「パターン間バッファ（秒）」（既定30）を入力できる |
| SIEGE-002 | メンバーごとに「ラベル／名前」、役割、「行軍秒数（ペットなし）」、「速度ペットLv」、採用を入力でき、「+ メンバー追加」で行を追加、「削除」で行を削除できる。追加した行の既定は役割「削り」、ラベル空、行軍0、速度ペットなし、採用はSIEGE-008の「全員同じ」がオンならその値、オフならオン |
| SIEGE-003 | パターンごとに名前と、役割が削りのメンバー、役割が増援のメンバーをそれぞれチェックボックスで選べる。「+ パターン追加」で`①`〜`⑳`の順に名付けて追加し、21個目以降は`(21)`の形式とする。追加したパターンでは、その時点の増援のメンバー全員を選んだ状態にする |
| SIEGE-004 | メンバーを削除した場合は、全パターンの削りと増援の選択からも外す |
| SIEGE-005 | 削りのメンバーがいない場合は「削り役割のメンバーがいません」、増援のメンバーがいない場合は「増援役割のメンバーがいません」、パターンがない場合は「パターンがありません」と表示する |
| SIEGE-006 | 保存データ（SIEGE-040）がないか、メンバーが0人の場合は、メイン1人（ラベル「メイン」）、増援1人（ラベル「増援」）、削りA〜F（行軍はすべて0）、パターン①（A、B、C）、②（D）、③（E、F）と、各パターンで増援を選んだサンプルを表示する |
| SIEGE-007 | 「速度ペットLv」は「持っていない」、Lv8、Lv7…Lv1の順に、各Lvのボーナスを`Lv{n}（+{ボーナス}%）`の形で選ぶ。「行軍秒数（ペットあり）」の欄は読み取り専用で、速度ペットがなければ「（ペットなし）」、あればSIEGE-019の秒数を四捨五入して表示する |
| SIEGE-008 | 「速度ペットの採用を全員同じにする」をオンにすると「全員「ペットあり」の秒数を使う」が現れ、その値を全員の採用へそろえ、行ごとの採用を変更できなくする |
| SIEGE-009 | 速度ペットのLvごとのボーナスを、「速度ペットのボーナス%を編集する（このブラウザだけ）」の欄でLv1〜Lv8ごとに変更できる。入力欄の範囲は0〜500（0.1刻み）だが、受け付けるのは0以上の有限の数で、500を超える値も使う。0以上の数でない入力は無視し、直前の値を保つ。既定値と違う間は「※初期値から変更中」と表示し、「初期値に戻す」で既定値へ戻す。変更すると、メンバーの欄を表示し直し、計算結果を表示していれば計算し直す |

### 3.2 計算規則

| ID | 要件 |
|---|---|
| SIEGE-010 | 集結時間（分）は60倍して秒へ換算する |
| SIEGE-012 | パターンの削りの最小着弾時刻Tは、0、選んだ各削りの`使用可能時刻 + 削りの集結時間 + 行軍`、各メインの`使用可能時刻 + メインの集結時間 + 行軍 - フェーズ間隔`、選んだ各増援の`使用可能時刻 + メインの集結時間 + 行軍 - 2 × フェーズ間隔`の最大値とする。使用可能時刻は、メンバーが次の集結に使える時刻で、最初は0秒とする |
| SIEGE-013 | 1周目、2周目の順に、各周のパターンを定義順（①②③…）に1件ずつ確定する。各パターンのTは、その時点の使用可能時刻からSIEGE-012で求める。2周目も1周目の続きの使用可能時刻から計算する |
| SIEGE-014 | 着弾は削りがT、メインが`T + フェーズ間隔`、増援が`T + 2 × フェーズ間隔`とする |
| SIEGE-015 | 発起は`着弾 - 集結時間 - 行軍`、帰還は`着弾 + 行軍`とする |
| SIEGE-016 | 確定したメンバーの使用可能時刻を`帰還 + パターン間バッファ`へ更新する |
| SIEGE-017 | 周期は、定義順で先頭のパターンの`2周目のT - 1周目のT`とする |
| SIEGE-018 | メインは、削りや増援の選択にかかわらず全パターンに参加する。メイン、削り、増援はいずれも0人でもよく、メインが0人でもメッセージを出さずに計算する |
| SIEGE-019 | 計算に使う行軍秒数（以下、行軍）は、採用がオンなら`行軍秒数（ペットなし） ÷ (1 + ボーナス ÷ 100)`を四捨五入した値、採用がオフなら行軍秒数（ペットなし）をそのまま使う。速度ペットがなければボーナスは0とする（採用がオンなら四捨五入はする）。ボーナスの既定値はLv1から順に15、17、19、21、23、25、27、30（%） |

#### 計算結果が満たす性質

`tests/web/`の検査は、出力テキストと入力だけから次の性質を確かめる。固定の例と、決定的な乱数で作った
入力（メイン1〜2人、増援0〜2人、削り1〜8人、パターン1〜5件、速度ペットの有無と採用を含む。メンバー表の並びと、パターンで削りと増援を選ぶ順は、どちらも入れ替える）で、違反が
0件であることを求める。

| ID | 性質 | 根拠の要件 |
|---|---|---|
| C1 | 発起が0秒より前にならない | SIEGE-012 |
| C2 | 2周分を通して、同じ人の次の発起が、前回の`帰還 + パターン間バッファ`以降になる | SIEGE-013、SIEGE-016 |
| C3 | パターンの削りは同時にTで着弾し、メインは`T + フェーズ間隔`、増援は`T + 2 × フェーズ間隔`で着弾する。発起と帰還はSIEGE-015の式に従う | SIEGE-014、SIEGE-015 |
| C8 | 「計算結果（1周目）」は、参考の1周目と同じ本文に`周期：`の行を付けたものである | SIEGE-020、SIEGE-021 |
| C9 | 行が1つ以上あるパターンがすべて出力にあり、各パターンの見出しと行（削り、メイン、増援）が入力と一致する。見出しの削りのラベルと、同じ発起で同じ役割の行はメンバー表の順に並ぶ | SIEGE-018、SIEGE-024 |
| C10 | 各パターンのTは、それより前に確定したパターンの帰還とパターン間バッファから求めた使用可能時刻で、SIEGE-012の最大値に等しい（着弾を必要以上に遅らせない） | SIEGE-012、SIEGE-013、SIEGE-016 |
| C11 | 表示した周期は、先頭のパターンの2周目と1周目の着弾の差に等しい | SIEGE-017 |
| C12 | 行軍は、採用と速度ペットからSIEGE-019の式で求めた値に等しい | SIEGE-019 |

C4〜C7は、置き換える前の確定順と周期の計算（1周目と2周目でパターンの順番が同じで、1周目を繰り返しても
待ち時間を守る最小の周期）の性質だった。現行の計算では満たさないことがあるため、検査から外した。C4（2周の
着弾の順番が同じ）は、2周目を計算し直すためブロックの並び（SIEGE-025）が周ごとに変わり得ることから外し、
C5〜C7はKI-SIEGE-14のため外した（ADR 0031）。番号は再利用しない。

### 3.3 出力

| ID | 要件 |
|---|---|
| SIEGE-020 | 「計算結果（1周目）」に1周目の全パターンを出し、空行を挟んで末尾へ`周期：{周期}`の行を付ける |
| SIEGE-021 | 「参考：2周分の計算結果」に`【1周目】`と1周目、空行、`【2周目】`と2周目、空行、`周期：{周期}`を確認用として出す。コピーの対象にしない |
| SIEGE-022 | 時刻は四捨五入した秒を`{分}分{秒2桁}秒`で表し、60分以上も時間へ繰り上げない |
| SIEGE-023 | 集結時間は秒が0なら`{分}分`、それ以外は`{分}分{秒}秒`で表す |
| SIEGE-024 | パターンごとの書式は次のとおりとする。見出しの削りのラベルはメンバー表の順に並べる。見出しの末尾は、そのパターンで増援を1人以上選んでいれば`→メイン→増援`、いなければ`→メイン`とする。パターン内の行は発起の早い順に並べ、同じ発起の行は削り、メイン、増援の順、同じ役割の中ではメンバー表の順とする。行が1つもないパターンは出さない |
| SIEGE-025 | パターンのブロックは、ブロック内で最も早い発起の順に並べ、同じ時刻なら定義順とする。ブロックの間は空行で区切る |

```text
{パターン名}{削りのラベルを+で連結}→メイン→増援
{発起} → {パターン名}{ラベル}（{集結時間}集結）※行軍{行軍秒数}秒（{着弾}着、{帰還}帰還）
```

行頭の時刻、`→`、パターン名の記号、`（{分}分集結）`は、周期ウェーブタイマーが行を読むために使う
（WAVE-031、WAVE-032）。この書式を変える場合は、両方の要件を同じ変更で更新する。周期ウェーブタイマーが
読める記号は`①`〜`⑳`だけのため、21個目以降のパターンと、名前を変えて記号を含まなくなったパターンは
読まれない（KI-WAVE-27）。

| ID | 要件 |
|---|---|

| SIEGE-031 | 「Discord用にコピー」で1周目の出力をクリップボードへコピーし、1.5秒間「コピーしました」と表示する |
| SIEGE-032 | パターンが0件の場合は、時刻を計算せずに出力欄へ「パターンが設定されていません。」と表示する。参考の結果と周期ウェーブタイマーへ渡す結果（SIEGE-045）は変えない |
| SIEGE-035 | 計算（「タイムラインを計算」と、SIEGE-009による計算し直し）のたびに、周期ウェーブタイマーへ渡す結果（SIEGE-045）を保存する。SIEGE-032のメッセージを出す場合は保存しない |

### 3.5 保存

| ID | 要件 |
|---|---|
| SIEGE-040 | メンバー、パターン、共通設定、「全員同じ」の設定を、変更のたびにlocalStorageのキー`siegeCalcState`へ保存し、次回表示時に復元する。計算結果は保存せず、再表示では結果カードを出さない |
| SIEGE-041 | `siegeCalcState`の保存形式は次のとおりとする。パターンに`reinforceIds`がない保存データは、その時点の増援のメンバー全員を選んだものとして読む。メンバーに`petLevel`がなければ0、`usePet`がなければ`true`とする |
| SIEGE-045 | 周期ウェーブタイマーへ渡す結果を、キー`siegeTimelineForWaveTimer`へ`{savedAt, periodSec, maxSec, rawText}`の形で保存する。`savedAt`は保存した時刻（ミリ秒）、`periodSec`は周期（秒）、`maxSec`は1周目の帰還の最大値（秒。行がなければ`null`）、`rawText`は「計算結果（1周目）」の本文とする |
| SIEGE-046 | 速度ペットのボーナス（SIEGE-009）を、キー`ksMarchPetBonus`へ9個の数の配列（先頭はペットなしの0、続いてLv1〜Lv8）として保存する。KvK同着スタート カウントダウン表と同じ値を使う。9個の0以上の数でない保存データは使わず、既定値とする。「初期値に戻す」でキーを削除する |

```text
siegeCalcState:
{memberSeq, patternSeq,
 members: [{id, role, label, march, petLevel, usePet}],
 patterns: [{id, name, kezuriIds, reinforceIds}],
 settings: {kezuriRallyMin, mainRallyMin, phaseGap, buffer},
 petSameForAll, petSameValue}
```

## 4. 既知の不具合と現行実装との差異

| ID | 内容 | 影響 |
|---|---|---|
| KI-SIEGE-01 | 削りや増援のメンバーを他の役割へ変えても、パターンの選択に残る。メインへ変えたメンバーが削りや増援としても計算され、画面からは外せない | 誤ったタイムライン |
| KI-SIEGE-03 | 「パターン間バッファ」は実際にはメンバーごとの帰還後の待ち時間として使われ、名称と挙動が一致しない | 設定の誤解 |
| KI-SIEGE-06 | 集結時間（分）は小数を切り捨てる。負数を拒否せず、発起時刻が負になると時刻表示が崩れる | 入力範囲が不明確 |
| KI-SIEGE-07 | 採用がオフで小数の行軍秒数を入れると、行軍の表示に浮動小数の誤差が出る可能性がある | 表示崩れ |
| KI-SIEGE-08 | パターンの削除後に追加すると、件数から名前を付けるため名前が重複する。周期ウェーブタイマーは同じ記号の行を1つのパターンにまとめる（WAVE-032） | 読み違い |
| KI-SIEGE-09 | ラベルが空のメンバーは、画面では「(無名)」だが出力では空文字になる | 読み違い |
| KI-SIEGE-11 | コピーに失敗しても通知しない | 誤ったFeedback |
| KI-SIEGE-13 | ファイル名の「攻城タイムライン計算」と表示名の「集結タイムライン計算」が一致しない | 保守時の混乱 |
| KI-SIEGE-14 | 周期（SIEGE-017）は先頭のパターンの着弾の差だけで決まる。2周目を計算し直すため、ほかのパターンの2周目と1周目の差は周期と違うことがあり、1周目を周期ずつずらして繰り返すと、待ち時間（`帰還 + パターン間バッファ`）を破る指示になることがある。周期ウェーブタイマーは1周目を繰り返す前提で表示する（置き換える前の旧SIEGE-017、性質C5〜C7で直していた。ADR 0031）。見分け方: 周期ウェーブタイマーのk個目の予定は、1周目を`(k - 1) × 周期`だけずらしたものになる。このため「計算結果（1周目）」で人ごとに`1周目の最初の発起 + 周期 >= 1周目の最後の帰還 + パターン間バッファ`を確かめれば足りる。満たす人は、2個目以降のすべての予定で待ち時間を守る。満たさない人は、2個目以降の予定で待ち時間（`帰還 + パターン間バッファ`）より前の発起を指示されるおそれがある（予定の間の空きに割り込む場合は守ることもあるため、この条件は十分条件である）。「参考：2周分の計算結果」の2周目の全行が1周目の同じ行に周期を足した時刻と一致する場合は、全員が満たす。例: 共通設定が既定値で、パターン①が削りA（行軍0）、②が削りB（行軍200）、メインM（行軍0）の場合、周期は7分00秒。Bは`10 + 420 = 430 < 710 + 30 = 740`のため、2個目で7分10秒、3個目で14分10秒と毎回、帰還（11分50秒、18分50秒）より前の発起を指示される。Mは`121 + 420 = 541 >= 511 + 30`のため守る。満たさない人への対処（周期を手で広げるなど）はQ-SIEGE-05で決める | 待ち時間を破る指示 |
| KI-SIEGE-15 | 置き換える前の版がタブの保存に使っていたキー`siegeCalcTabs`を読まない。タブで作った計算機と計算結果は表示されず、タブを加える前の`siegeCalcState`の内容を表示する（ADR 0031） | 保存した入力が見えない |
| KI-SIEGE-16 | メンバーを全員削除して再表示すると、サンプルに戻る（置き換える前の旧KI-SIEGE-10と同じ） | 入力の消失 |
| KI-SIEGE-17 | 置き換える前の版との差異: メインのメンバーがいなくても計算する（SIEGE-018）。置き換える前はメインを必須とし、メッセージを出していた（旧SIEGE-033）。メインが0人で、先頭のパターンで削りも増援も選ばないと周期が0になり、周期ウェーブタイマーは周期を変えずに、MAXとタイムラインを取り込む（WAVE-081） | メインのない作戦の指示 |
| KI-SIEGE-18 | 速度ペットのボーナスを別のページ（KvK同着スタート カウントダウン表）で変えても、開いているページには再表示まで反映しない。古い値のまま1つのLvを変えると、9個すべてを保存し直すため、別のページで変えた値も上書きする | 古いボーナスで計算 |
| KI-SIEGE-19 | 計算した後にメンバー、パターン、共通設定を変えても、結果カードに注意を出さない。古い結果をコピーでき、周期ウェーブタイマーへ渡した結果も古いまま（置き換える前の旧SIEGE-043） | 古いタイムラインの共有 |

## 6. 決定済みの事項

| 事項 | 決定 | 反映先 |
