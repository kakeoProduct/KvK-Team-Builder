# 要件定義: 隊の編成ルール

参加者を隊へ割り当てる規則を定める。元のルール文書は「チーム編成ロジック」のA（基本ルール）、
B（v2）、C（2026-10-10確定分）、D（モード切り替え）と、「同盟メンバー表 整形ルール」の
「組み分けの条件」である。新しい規則（B、C）と古い規則（A）が食い違う場合は新しい方を採用し、
利用者の決定（[未決事項](open-questions.md)の「決定済みの事項」）を最優先とした。分類の意味は
[総則](README.md)の2.1を参照する。「上限」「最低ライン」などの値は設定値であり、本書には書かない。

## 1. 隊とリーダー

| ID | 分類 | 要件 |
|---|---|---|
| FRM-001 | 必須条件 | 隊の数はリーダーの人数とし、リーダー一覧の番号を隊の番号とする。リーダー一覧は設定として持つ。リーダー一覧の順は運用者が決める（FRM-006） |
| FRM-002 | 必須条件 | リーダーは自分の隊に所属する。遅れる、または途中で抜けるリーダーも自分の隊に所属し、不在の時間帯はリーダー不在として扱う。置き方を運用者に問い合わせない（旧Q-043で決定。旧Q-016のうちリーダーの置き方を置き換える）。参加時間未定のリーダーは別枠（FRM-060）に置き、全時間帯をリーダー不在とする（旧Q-053で決定） |
| FRM-003 | 廃止 | リーダーが不在の時間帯に、アプリが運用者に問い合わせて代理リーダーを指定する規則は、当面採用しない。リーダー不在の時間帯は代理を決めずに出力する（旧Q-032で決定。旧Q-016のうち代理リーダーを置き換える） |
| FRM-004 | 運用操作 | グループ分けは、運用者の指示がない限り行わない。通常モードのグループは、運用者が画面で作るUI-013のグループと同じもので、治療時間の目安の計算だけに使う（旧Q-054で決定）。総力モードはFRM-080〜FRM-087を参照 |
| FRM-005 | 運用操作 | 隊数を減らす選択肢（FRM-090）を運用者が選んだ場合は、番号の最も大きい隊をなくし、そのリーダーと所属メンバーも含めて、残りの隊で編成をやり直す。FIXの隊かどうかにかかわらず番号の大きい順とし（作成者の仮定A-07。FRM-072の例外とする）。FRM-039の対象で、FRM-046で許していない6人以下が残る限り、続けて減らす（旧Q-068、旧Q-079、旧Q-085で決定）。第1〜3隊は減らさない（旧Q-084）。なくした隊に付いていた運用者の指定は失効する（作成者の仮定A-03）。戦闘の開始前に隊の数を決め直す操作で、FRM-013とFRM-044の例外ではない。FRM-001の例外とする |
| FRM-006 | 運用操作 | リーダー一覧の順（隊の番号）は運用者が決め、総力モードでも振り直さない（旧Q-094で決定。FRM-084を廃止）。運用者は、取得したMystic Trialの順位（ROS-053）を参考にしてよい。Mystic Trialはリーダーの順を決める参考にだけ使い、メンバーの強さ（平均G、FRM-027）には使わない |

## 2. 所属と時間帯

| ID | 分類 | 要件 |
|---|---|---|
| FRM-010 | 必須条件 | 参加時間が確定したメンバーは、ちょうど1つの隊に所属するか、待機（FRM-033）になる。所属は時間帯をまたいで変わらない。同盟移動協力者（FRM-087）は対象外とし、待機にも数えない |
| FRM-011 | 必須条件 | 各時間帯の隊の出撃メンバーは、その隊の所属メンバーのうちその時間帯に参加しているメンバーと、その時間帯にその隊を応援するメンバー（FRM-042）とする。参加しているのに出撃しないメンバー（時間帯ごとの待機）は作らない（旧Q-014で決定） |
| FRM-012 | 表示のみ | 隊ごとに、所属人数と、時間帯ごとの出撃人数、出撃メンバーの平均G、VC可能人数を算出する。別枠のメンバーは含めない。出撃開始前の時間帯（FRM-041）は、時間帯ごとの値を算出しない |
| FRM-013 | 必須条件 | 隊は戦闘の途中で解散せず、ほかの隊と統合しない（旧Q-024で決定）。出撃人数の下限（FRM-039）を満たせない場合も解散や統合で解決せず、運用者に選択肢を示す（旧Q-034で決定） |

## 3. 上位隊（第1〜3隊）

| ID | 分類 | 要件 |
|---|---|---|
| FRM-020 | 必須条件 | 第1〜3隊は、リーダーを含めて各8人に固定し、全時間帯で入れ替えない。リーダーが不在の時間帯（FRM-002）は、序盤を含む全時間帯で7人を許し、FRM-029の警告を出す（旧Q-015、旧Q-032で決定） |
| FRM-021 | 必須条件 | 上位隊のメンバーは「戦闘時間を通じて常時稼働」かつ「VC参加可能（◇）」とする。指定リーダーは必ず含め、常時稼働の例外はリーダーだけとする（旧Q-004で決定）。参加時間未定で別枠に置いたリーダー（FRM-002）は含めず、その隊は全時間帯を7人とし、FRM-029の警告を出す（旧Q-062で決定） |
| FRM-022 | 必須条件 | リーダー以外の上位隊のメンバーは、最後の1時間だけ抜ける場合でも常時稼働とみなさない。v2にあった第1隊の例外は採用しない（旧Q-004で決定） |
| FRM-023 | 目的関数 | 上位隊の条件を満たすメンバーから、G8→G7→G6→G5の順に第1隊から割り当てる |
| FRM-024 | 目的関数 | T11を持つメンバーを、番号の小さい隊へ寄せる（旧Q-056で決定）。第1隊も含めてGを優先し、同じGのメンバーどうしでは、T11の順位が上のメンバーを優先する。T11の順位は、`(T11)`、2種、1種の順とし、1種どうしでは`(歩T11)`（`(盾T11)`）を`(弓T11)`や`(騎T11)`より上とする（旧Q-021、旧Q-056、旧Q-071、旧Q-083で決定）。T11を持たないメンバーは最下位とし、2種どうしと、`(弓T11)`と`(騎T11)`は同じ順位とする（作成者の仮定A-11） |
| FRM-025 | 運用操作 | 運用者が「常時参加が怪しい」と指定したメンバーは、上位隊から外して第4隊以降へ置く |
| FRM-026 | 必須条件 | 上位隊（第1〜3隊）の条件を満たすメンバーが足りない場合は、規則を緩めた編成を出さず、不足人数と理由を示して出力しない。上位隊の固定とVC必須は外さない（旧Q-084で決定）。運用者は参加者一覧や指定を見直して再編成する（作成者の仮定A-01） |
| FRM-027 | 必須条件 | 隊の戦力は、その時間帯の出撃メンバーの平均Gとし、各時間帯で「第1隊 > 第2隊 > 第3隊 >= 第4隊」を満たす（旧Q-003で決定）。平均Gは分数のまま比べる。第1隊と第2隊、第2隊と第3隊で平均Gが等しい場合は、T11の比率が高い隊を上とみなし、比率も分数のまま比べる。T11の比率は、出撃メンバーのT11を持つ兵種（歩兵、騎兵、弓兵）の数の合計を、出撃人数の3倍で割った値とする。`(T11)`は3、`(歩T11)`は1、`(弓T11)`など1種だけは1、2種は2として数える（ROS-012、ROS-042、旧Q-056、旧Q-071で決定）。比率も等しい場合は同じ戦力とみなし、「>」を満たさない。満たせない場合はFRM-026と同じく理由を示して出力しない（旧Q-020、旧Q-037、旧Q-048、旧Q-084で決定）。第3隊と第4隊は平均Gだけで比べ、等しくてもよい（旧Q-037で決定）。出撃開始前の隊（FRM-041）と、第4隊がない場合の第4隊は比較から除く。現行のTier戦力の合計による`A > B >= C`を置き換える |
| FRM-028 | 廃止 | 固定する上位隊の数を減らす、隊ごとにVC必須を外す選択肢は、上位隊は常に規則を守り固定をなくさないとする決定（旧Q-084）により採用しない |
| FRM-029 | 警告 | 上位隊でリーダーが不在の時間帯（FRM-002、FRM-020、FRM-040）に出撃人数が7人になる場合は、警告つきで出力する（旧Q-015、旧Q-032で決定）。同じ時間帯にFRM-035やFRM-043の警告にも当たる場合は、両方を出す（旧Q-066で決定） |

## 4. 第4隊以降の人数

| ID | 分類 | 要件 |
|---|---|---|
| FRM-030 | 必須条件 | 第4隊以降の人数は、各時間帯の出撃人数で数える（旧Q-002で決定）。出撃人数の上限は設定値とし、全隊共通の値と隊ごとの上書きを持てる。隊ごとの上書きは8〜9人の範囲とし、8人の上書きは出典の「8名固定」に当たる（旧Q-051で決定）。範囲外の値と、全隊共通と同じ値の上書きの扱いは、設定値の置き場所とあわせて実装Issueの1のADRで決める。8人は下限である（旧Q-038で決定）。運用者が明示した上限超え（FRM-036）を除き、上限を超えない（旧Q-013で決定）。下限はFRM-031、FRM-035、FRM-039、FRM-040、FRM-090に従う |
| FRM-031 | 目的関数 | 出撃人数がリーダーを含めて8人未満になる（隊、時間帯）の数を最小にする（FRM-037①のア、ウ）。8人は下限の基本とする（旧Q-001、旧Q-013で決定） |
| FRM-032 | 廃止 | 上限を「大きく超えない」目的関数は、上限を必須条件とする決定（旧Q-013）によりFRM-030へ統合した |
| FRM-033 | 目的関数 | 待機（どの隊にも所属できなかったメンバー）の人数を最小にする。ゼロでもよい。1隊を上限まで厚くして吸収し、それでも端数が出る場合だけ待機として人数を示す。待機にするメンバーは、Gの低いメンバーから選ぶ（FRM-037②、旧Q-104）。運用者は、待機に固定するメンバーと、待機にしてよいメンバーを指定できる（FRM-076） |
| FRM-034 | 目的関数 | 第4隊以降は、リーダー一覧の順で並べ、高Gのメンバーほど番号の小さい隊に寄せる |
| FRM-035 | 警告 | 序盤（FRM-040）以外で延長境界時刻（FRM-043）より前の時間帯に、出撃人数がリーダーを含めて7人になる場合は、警告つきで出力する（旧Q-012で決定、FRM-090の場合3） |
| FRM-036 | 運用操作 | 運用者が意図的に上限を超えて置いた場合は、FRM-030の例外として警告（保留）にする。例外は隊と時間帯の単位で記録し、画面とテキストに表示する。総力モードでは、運用者は（隊、時間帯）を指定する代わりに、上限超えを許す出撃人数の最大値（全隊共通の上限より大きい値）だけを指定してもよい。この場合はアプリが超える（隊、時間帯）を選び、その数を最小にする（FRM-104のア）。アプリが選べるのは、第4隊以降のうち、隊ごとの上限の上書きがなくFIXでない隊だけとする（旧Q-117）。上限を超えてよいのは所属メンバーだけで、応援を受けて上限（FRM-030）を超える（隊、時間帯）は作らない。アプリが選べる隊では、この上限は全隊共通の上限に当たる。応援先の空きはFRM-042のとおり上限（FRM-030。隊ごとの上書きを含む）で判定し、上限超えを許す最大値は使わない（旧Q-119）。最大値が全隊共通の上限以下の指定は入力のエラーとする（作成者の仮定A-24）。アプリが選んだ（隊、時間帯）も例外として記録し、表示する（旧Q-103） |
| FRM-037 | 目的関数 | 目的関数は次の指標を上から順に比べ、上位の指標を下位の指標のために犠牲にしない（旧Q-005で決定）。①人数不足。次のアからウをこの順に比べる（旧Q-087、旧Q-091で決定）。ア: 延長境界時刻より前で、出撃人数8人未満の（隊、時間帯）の数（FRM-031。休止を含む）。イ: 休止の（隊、時間帯）の数（FRM-048）。ウ: 延長境界時刻以降で、出撃人数8人未満の（隊、時間帯）の数（休止を含む）。例1: 延長境界時刻以降に7人の隊と1人の隊がある編成と、1人を移して8人の隊と休止にする編成では、アは同じで、イで前者が少ないので前者を選ぶ。例2: 判定に使う編成で、延長境界時刻より前の同じ（隊、時間帯）が1人の編成と休止の編成は、アが同じで、イで1人の編成を選ぶ。例3: 延長境界時刻以降の休止を1つ減らす代わりに延長境界時刻より前の7人が増える編成は、アで負けるので選ばない②待機人数（FRM-033）。待機人数が同じなら、待機のメンバーのGの合計が小さい編成を選ぶ。待機にしてよいと指定したメンバー（FRM-076）は、どちらにも数えない（旧Q-104）③番号の小さい隊ほど出撃メンバーの平均Gが高い順序からの逆転の数。時間帯ごとに、出撃中の隊の組のうち、番号の小さい隊の平均Gが番号の大きい隊の平均Gより低い組を数え、全時間帯で合計する（FRM-023、FRM-034。旧Q-047で決定）④同じGのメンバーの組のうち、T11の順位（FRM-024）が上のメンバーが下のメンバーより番号の大きい隊に所属する組の数。リーダー、別枠、同盟移動協力者は除き、待機は最後の隊の次の番号として扱う（FRM-024、旧Q-056）⑤延長境界時刻より前で、出撃中の隊の◆のいない（隊、時間帯）の数（FRM-050）⑥FRM-051を満たさない隊の数⑦前回の編成からの移動の数（FRM-071）⑧延長境界時刻以降で、出撃中の隊の◆のいない（隊、時間帯）の数（FRM-045、旧Q-072で決定）⑨（セット（FRM-073）、時間帯）のうち、応援するメンバーが1人以上いるものについて、使う応援先の数から1を引いた値の合計。例: 3人のうち2人が第5隊、1人が第6隊なら1、応援する人がいなければ数えない（旧Q-077、旧Q-086で決定）⑩応援先の分かりにくさ。応援するメンバーごとに、隣り合う時間帯で応援先が変わる回数と、同じ応援先へ続けて応援する区間のうち長さが1時間帯（30分）のものの数を足し、全員で合計する。応援しないメンバーは0とする。例: 第5隊、第6隊、第5隊と30分ずつ応援すれば、変わる回数2と長さ1の区間3で5（旧Q-089の意図による。数え方と優先度は作成者の仮定A-08）。⑨⑩は、所属の選び方と、問い合わせで示す推奨の応援先の評価に使い、運用者が選んだ応援先は変えない。いずれも小さいほどよい。総力モードでは、待機の指標と平均Gの順序の指標の間にFRM-104の指標を挟む。運用者の選択で前回の編成からの移動の指標を前へ移す場合はFRM-071に従う |
| FRM-038 | 非機能 | 同じ入力と同じ設定からは、OS、Pythonの版、探索の並列数と時間制限、計算機の負荷にかかわらず、毎回同じ編成を出す（旧Q-005で決定、#41）。FRM-037の指標がすべて等しい編成が複数ある場合は、参加者一覧の出現順にメンバーの所属する隊の番号を並べた列（待機は最後の隊の次の番号として扱い、別枠と同盟移動協力者は含めない）を前から比べ、最も小さい編成を選ぶ。総力モードで所属の列も等しい場合は、待機、別枠、同盟移動協力者の移動先の同盟（グループの設定の順の番号）を参加者一覧の出現順に並べた列を前から比べ、最も小さい編成を選ぶ。最適な編成が複数ある小さな架空の入力について、最適な編成を実装とは別の方法ですべて列挙し、そのうち所属の列（総力モードでは所属の列と移動先の列をこの順に比べて）が最も小さいものを期待値とする。その期待値と、チャット共有用テキストが、CIのすべての組み合わせで一致することで確かめる。下限に満たない小さな架空の入力でも、判定に使う編成と選択肢を実装とは別の方法で列挙して期待値とし、問い合わせの番号付きの質問（FRM-075）の文面が一致することを確かめる。A-10の例（例1と例3は2回目、例2は3回目の実行で出力し、例4は問い直す）を受け入れテストにする。FRM-090の性質(1)(2)(4)は、下限に満たない小さな架空の入力で、示した選択肢のすべての組み合わせを自動で答えて確かめる。判定に使う編成、選択肢の列挙、回答を確かめる探索はFRM-090に従い、最適性を示せなければ時間切れのエラーとする。検証用の架空の入力は、CIのすべての組み合わせで最適性を示せる大きさに限る。制限内に最適性を示せない場合はFRM-049に従う。探索の設定とテストの並列数は、ADR 0019の見直し（実装Issueの3）で決める。Validatorの対象ではない |
| FRM-039 | 必須条件 | 延長境界時刻より前の時間帯で、出撃中の隊の出撃人数がリーダーを含めて6人以下になってはならない。休止（FRM-048）もこれに含める（旧Q-028、旧Q-035、旧Q-088で決定）。出撃開始前（FRM-041）の時間帯と、運用者が明示して許した（隊、時間帯）（FRM-046）は対象外とする。満たせない場合は、隊を解散せずに（FRM-013）、FRM-090の表の選択肢を運用者に示し、選ぶまで出力しない（旧Q-034、旧Q-060、旧Q-081で決定） |

## 5. 序盤と後半の時間帯

| ID | 分類 | 要件 |
|---|---|---|
| FRM-040 | 必須条件 | 序盤（戦闘開始からの1時間。20:00に始まる回は20:00〜21:00、21:00に始まる回は21:00〜22:00）は、出撃中の各隊の出撃人数がリーダーを含めて8人未満になってはならない（旧Q-080で決定。旧Q-042、旧Q-045、旧Q-058の序盤の範囲を置き換える）。序盤は、リーダーが不在でも隊として出撃させる（旧Q-090で決定。21:00開始の回への当てはめは作成者の仮定A-13）。上位隊のリーダーが不在の時間帯は7人を警告つきで許す（FRM-029）。出撃開始前の隊は対象外とし、休止はFRM-039とFRM-090に従う。満たせない場合はFRM-090の表に従う |
| FRM-041 | 運用操作 | 序盤に8人未満の隊がある場合は、アプリが理由と選択肢（遅れて出撃させる隊、出撃開始時刻、応援先）を示し、運用者が選ぶまで出力しない（旧Q-017、旧Q-075、旧Q-080で決定）。一緒に示す選択肢はFRM-090に従う。第1〜3隊とFIXの隊（FRM-072）は、運用者が選ぶ遅れて出撃する隊にしない（旧Q-076、旧Q-084）。応援するメンバーがいるのに応援先の候補がない案は選択肢に含めない。隊は出撃開始時刻を持ち、FRM-012、FRM-027、FRM-031、FRM-039、FRM-040、FRM-050、FRM-056は出撃開始以降の時間帯にだけ適用する |

| FRM-048 | 必須条件 | 出撃開始後に、所属メンバーのうちその時間帯に参加している人数が0人になる時間帯を休止という。応援は含めずに判定する。延長境界時刻より前の休止は、6人以下（FRM-039）と同じく扱い、FRM-090の選択肢を示して選ぶまで出力しない（旧Q-088で決定）。運用者が明示して許した場合（FRM-046）と延長境界時刻以降は、休止として出力し、再び参加するメンバーがいる時間帯から出撃を再開する（旧Q-070で決定）。同じ時間の範囲（延長境界時刻より前、以降）の中では、7人で出撃させる代わりに休止させる編成を選ばない（旧Q-087で決定）。延長境界時刻以降の休止を減らすために、延長境界時刻より前の8人未満を増やす編成も選ばない（旧Q-091で決定）。どちらもFRM-037の①で比べる。休止中の時間帯には、FRM-012、FRM-027、FRM-050、FRM-053、FRM-056と、FRM-037の③⑤⑧を適用しない。休止中の隊は応援先にならない。延長境界時刻以降の休止にも延長保留（FRM-043）を出し、休止した時間帯はテキストと画面に「休止」と示す（作成者の仮定A-06）。序盤はリーダーが不在でも隊として出撃させるため（旧Q-090）、FIXでない隊が序盤に所属メンバー0人になる編成（戦闘時間を通して0人の隊を含む）は、休止と同じく6人以下として扱う。序盤に所属メンバーが0人のFIXの隊は、遅れて出撃する隊として扱い、出撃開始時刻は所属メンバーが最初に参加する時間帯とし、運用者に問い合わせない。戦闘時間を通して所属メンバーが参加しないFIXの隊は、出撃開始時刻を決められないため、序盤の6人以下（FRM-090の場合2）として扱う（作成者の仮定A-02） |

## 11. 同盟移動（総力モード）

総力モードで、グループ（FRM-083）ごとに移動先の同盟へメンバーを移す規則を定める。同盟名などの運用値は
設定値とし、本書には書かない。

グループのない総力モードでは同盟移動を行わず、FRM-100〜FRM-103、FRM-104のウとエ、FRM-105、FRM-106、
OUT-016〜OUT-018を当てはめない。グループを前提にするFRM-081、FRM-082、FRM-086と、FRM-042とFRM-047のうち
応援先を同じグループの隊に限る部分も当てはめず、応援先は通常モードと同じ条件で選ぶ。FRM-104のア（上限を
超える（隊、時間帯）の数）とイ（上位隊のGの合計）は当てはめる。協力者同盟（ROS-007）のブロックと協力者の欄
（ROS-004）は、同盟移動を行わないためROS-060で確認に回す。グループと同盟移動にだけ使う指定（移動先の個別指定、
同じ同盟へ移さない組、移動先が分かれてよい同盟、移動後の同盟の総力の目標と人数の上限、グループの人数の上限、
1グループの隊の数の上限、グループの総力の最低ライン、協力者の欄の移動先（`cooperator_destinations`））を、その実行で運用者が渡した場合（`settings.json`など）は、
黙って無視せず、指定の名前を示して入力のエラーとする。通常モードで渡した場合も同じとする。Repositoryに置く
常設の既定値は、グループのない総力モードでは使わず、エラーにもしない。協力者同盟の設定（ROS-007）は
エラーにせず、そのブロックを見分けて確認に回すために使う。グループのない総力モードとは、グループ（DAT-007の
`groups`）が未指定か空の一覧の総力モードをいう（作成者の仮定A-22）。
