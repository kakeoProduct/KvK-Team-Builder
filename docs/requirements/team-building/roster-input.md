# 要件定義: 参加者の入力

参加者一覧（同盟メンバー表）から、編成に使うメンバーの情報を読み取る要件を定める。元のルール文書は
「同盟メンバー表 整形ルール」と「チーム編成ロジック」の「渡される情報」「参加時間の読み方」
「時間記載なしの扱い」「兵士レベル」である。同盟名、呼び名などの運用値は設定として持ち、本書には書かない。

## 1. 参加者一覧の構成

| ID | 分類 | 要件 |
|---|---|---|
| ROS-001 | 入力正規化 | 参加者一覧は同盟ごとのブロックで、各ブロックは兵士レベル（G8、G7、G6、G5、その他）の行にメンバー名を「、」区切りで並べる。該当者がいない行は空のまま残してよい |
| ROS-002 | 入力正規化 | 同じ同盟でも「最初から参加できる」と「途中参加」でブロックを分けられる。参加区分の指定がない同盟は「最初から参加できる」とみなす |
| ROS-003 | 入力正規化 | 「21時から参加」のように時刻が書かれたブロック見出しは、その時刻からの参加として扱う。時刻のない「途中参加」ブロックでは、個別の時刻の記載がないメンバーを参加時間未定とする（旧Q-022で決定）。個別の時刻の記載があれば、その時刻を使う |
| ROS-004 | 入力正規化 | 「その他」の後に「同盟移動協力者」の欄を置ける。協力者は「名前(数字)」の数字をGとして読む。協力者の欄は「途中参加」ブロックには置かない。協力者は隊に入れない（FRM-087）。通常モードの入力に協力者の欄がある場合は、ROS-060で確認に回す（旧Q-055で決定）。協力者同盟（ROS-007）のブロックのメンバーは、この欄によらず協力者として読む。グループのない総力モードでは、協力者の欄もROS-060で確認に回す（作成者の仮定A-22） |
| ROS-005 | 入力正規化 | 参加同盟の顔ぶれと、同盟の正式名と略称の対応は設定として持ち、略称を正規化する |
| ROS-006 | 入力正規化 | ゲーム内名と運用上の呼び名の対応表を設定として持ち、同じメンバーかどうかの照合だけに使う。出力では呼び名へ置き換えず、参加者一覧の記載のまま書く（旧Q-029で決定）。総力モードでは、対応表にゲーム内のID（外部の集計サイトのIDを含む）も持ち、総力などの照合に使う（ROS-053） |
| ROS-007 | 入力正規化 | 総力モードでは、運用者が設定で協力者同盟に指定した1同盟のブロックは、通常の参加者一覧と同じ書き方（ROS-001〜ROS-033）で書かれていても、全員を同盟移動協力者（FRM-087）として読む。協力者同盟は1同盟だけとし、2同盟以上の指定は入力のエラーとする。移動先の同盟もあわせて設定する（旧Q-098）。通常モードでは協力者同盟を扱わず、そのブロックはROS-060で確認に回す（旧Q-114）。グループのない総力モードでも、同盟移動を行わないため確認に回す（作成者の仮定A-22）。記号と参加時間は読み取るが、編成には使わない |

## 2. メンバー名の後ろの情報

| ID | 分類 | 要件 |
|---|---|---|
| ROS-010 | 入力正規化 | 名前の後ろの情報は「名前 → 記号 → 時間の括弧 → 兵種／T11の括弧 → 総力の括弧」の順で読む。例: `ユウ◯△(〜22時)(T11)`、`ミナ◯◇(23時〜)(歩弓)` |
| ROS-011 | 入力正規化 | 記号は◯（マンスリー持ち）、△（途中抜け）、◇（VC参加可能、聴き専可）、◆（ビビアン星4以上持ち）を読む。以前の表記の★も◆と読む（旧Q-095） |
| ROS-012 | 入力正規化 | 兵種とT11の括弧は、`(T11)`＝3種T11、`(歩T11)`＝歩兵のみT11と読む。`(歩弓)`と`(盾弓)`はT11ではなく兵種の記載で、歩兵と弓兵が記載のGであることを表す（旧Q-027で決定）。`歩11`は歩T11と読む。`(騎T11)`、`(弓T11)`、`(歩弓T11)`のように兵種を付けたT11は、その兵種のT11として読む。歩兵は「盾」とも書く（例: `(盾T11)`は`(歩T11)`、`(盾弓T11)`は`(歩弓T11)`）。`盾11`は`歩11`と同じく読み、`弓11`は`(弓T11)`と読む（旧Q-071、旧Q-082で決定）。`騎11`も`(騎T11)`と読む（作成者の仮定A-09）。これら以外のT11の記載はROS-060で確認に回す |
| ROS-013 | 入力正規化 | 「歩」だけの記載は、歩兵だけが記載のGであることを表す |

## 3. 戦闘時間と参加時間

| ID | 分類 | 要件 |
|---|---|---|
| ROS-020 | 入力正規化 | 戦闘時間（開始と終了）は毎回変わる設定値とする。戦闘開始は20:00か21:00のどちらかとし、それ以外の値の扱いは、設定値の置き場所とあわせて実装Issueの1のADRで決める（旧Q-058で決定）。参加時間は30分単位で管理し、21:30〜23:30のような半端な時間もそのまま扱う。30分単位でない時刻（例: 21:15）はROS-060で確認に回す |
| ROS-021 | 入力正規化 | 「〜23時」は開始から23時まで、「22時〜」は22時から最後まで、「21時〜24時」はその間として読む |
| ROS-022 | 入力正規化 | 戦闘の開始時刻より小さい時刻は、24を足して日をまたいだ時刻として読む（例: 「23時〜0時」の0時は24時、「2時」は26時）。表示も24:30、25:00のように24時以降の数字で書く（旧Q-009で決定） |
| ROS-023 | 入力正規化 | 括弧内が時刻だけ（例: `(24時)`）の場合は「〜その時刻」と読む |
| ROS-024 | 入力正規化 | 「X時予定」は「X時〜」と読む。「22〜24寝落ちまで」は22〜24時と読む |
| ROS-025 | 入力正規化 | 戦闘時間外の時刻（例: 「10時〜」）は誤記の可能性があるため、推測で補わず確認に回す |

## 4. 時間の記載がない場合と参加不可

| ID | 分類 | 要件 |
|---|---|---|
| ROS-030 | 入力正規化 | △がなく時間の記載もないメンバーは、戦闘時間の全体に参加するとみなす（時刻のない「途中参加」ブロックはROS-003に従う） |
| ROS-031 | 入力正規化 | △があり時間の記載がないメンバーは、参加時間未定とする |
| ROS-032 | 入力正規化 | △があっても時間の記載があれば、その時間で参加するとみなす |
| ROS-033 | 入力正規化 | 「未定」「時間不明」の記載は、△の有無にかかわらず参加時間未定とする |
| ROS-035 | 入力正規化 | 参加不可のメンバーは、運用者が参加者一覧に含めない（旧Q-023で決定）。参加者一覧に載っているメンバーは参加する前提で読む |

## 5. 兵士レベル（G）

| ID | 分類 | 要件 |
|---|---|---|
| ROS-040 | 入力正規化 | G8〜G5はそのまま数値とし、「その他」はG4として計算する |
| ROS-041 | 入力正規化 | 兵種ごとにGが違うメンバーは、歩兵のGを採用する |
| ROS-042 | 入力正規化 | 弓兵だけがT11のメンバーも、T11の兵種の数を1として数える。Gは歩兵基準で判定する（ROS-041）。出典の「弓のみT11は歩兵基準ではT11扱いしない」は採用しない（旧Q-071で決定） |

## 6. 総力

| ID | 分類 | 要件 |
|---|---|---|
| ROS-050 | 入力正規化 | 総力モードでは、各メンバーの総力（拳マーク）を`(491.3M)`の形で読む。未取得のメンバーは空欄のまま扱う。総力は、参加者一覧の記載のほか、外部の集計サイトから取得したデータ（ROS-053）やスクリーンショット（ROS-051）から得てもよい。値の取得元と取得時刻を記録し、出力に取得日を添える（旧Q-093）。1人の総力は1つの値に決め、FRM-081、FRM-104、OUT-018で同じ値を使う。取得したデータがあれば参加者一覧の記載より優先し、取得したデータが複数あれば取得時刻が最も新しい値を使う（旧Q-120）。参加者一覧の記載は取得したデータに含めず、取得元を`manual`、取得時刻を参加者一覧を受け取った時刻（DAT-007の`roster_received_at`）とする。参加者一覧の記載の総力を使うのに受け取った時刻がなければ、入力のエラーとする。実行時刻やファイルの更新時刻で代えない（作成者の仮定A-27）。同じ取得時刻の値が複数ある場合と、時差のない時刻はA-28による |
| ROS-051 | 入力正規化 | スクリーンショットから総力やGを読み取る場合、城アイコンの数字をGとする。アプリでの読み取りは任意の機能とし、実現が難しければ運用者が数値を入力する（旧Q-010で決定）。外部の集計サイト（ROS-053）が使えなくなった場合に備え、総力、Mystic Trial、同盟の名簿（ROS-054）も、スクリーンショットからの読み取りか運用者の入力で得られるようにする（旧Q-093） |
| ROS-052 | 入力正規化 | 入力に総力の合計行や集計行がある場合は、参加者として読まず、ROS-060で確認に回す |
| ROS-053 | 入力正規化 | 総力モードでは、総力、Mystic Trial、同盟の名簿（ROS-054）を外部の集計サイトから取得してもよい。取得は任意の機能とし、取得に失敗した場合と一部だけ取得できた場合は、理由を示して止め、古いデータと混ぜない。古いデータは、失敗した取得の前のファイルを指し、DAT-006で残す取得の単位の外の行は混ぜることに当たらない（作成者の仮定A-26）。ほかの取得元へ自動で切り替えず、運用者がROS-051の方法を選ぶ（ADR 0027）。メンバーは名前ではなくゲーム内のIDで照合し、同じ名前の別人は同盟で区別する。照合の相手は名前の対応表と、名簿を取得した同盟では同盟の名簿、取得していない同盟では総力のデータとし（作成者の仮定A-19、A-28）、総力は総力のデータと同盟の名簿の両方を取得したデータとしてROS-050で1人1つの値に決め、どちらにも参加者一覧にも総力がないメンバーを総力の未取得、総力のデータにいないメンバーをMystic Trialの未取得として扱う（作成者の仮定A-26）。参加者一覧の同盟と取得した同盟（同盟の名簿と総力のデータの同盟。作成者の仮定A-28）が違うメンバー、名簿を取得した同盟（2つの同盟の名簿に載るメンバーは作成者の仮定A-28で決めた同盟）に参加者一覧で属しているのにその名簿にいないメンバーはROS-060で確認に回し、運用者が同盟を選ぶまで出力しない（旧Q-115）。参加者一覧の2人以上が照合で同じ人に当たる場合も確認に回し、名前の対応表か参加者一覧を直すまで出力しない（作成者の仮定A-29）。照合できないメンバー（2件以上に当たる場合。0件の扱いとあわせて作成者の仮定A-28）もROS-060で確認に回し、名前の対応表を直すまで出力しない（作成者の仮定A-28）。選んだ同盟はDAT-007の`alliance_choices`に書き、移動前の名簿の人数と総力の合計でもその同盟に数え、今の同盟もその同盟とする。書ける値と誤りの扱いは作成者の仮定A-28による。名簿を取得していない同盟のメンバーは、名前の対応表で照合し、その`game_id`（空欄なら作成者の仮定A-29。対応表に行がなければ参加者一覧の名前と同盟）で総力のデータを引く（作成者の仮定A-19）。Mystic Trialはリーダーの順を決める参考（FRM-006）にだけ使う（旧Q-093） |
| ROS-054 | 入力正規化 | 総力モードで同盟移動を行う場合は、移動先の同盟ごとに移動前の名簿（編成に参加しないメンバーを含む人数と各メンバーの総力）を入力として受け取り（作成者の仮定A-19）、移動後の同盟の人数と総力（FRM-103、FRM-104）の計算に使う（旧Q-100） |
| ROS-055 | 非機能 | 参加者一覧、名前の対応表、取得した総力とMystic Trial、同盟の名簿、運用者の指定、編成結果など、実運用の個人名を含むデータは、バージョン管理の対象外に保持する。Repositoryには形式（[data-formats.md](data-formats.md)）と架空の例だけを置く（旧Q-106、ADR 0027） |

## 7. 判別できない入力

| ID | 分類 | 要件 |
|---|---|---|
| ROS-060 | 入力正規化 | 判別できない、または不明な記載は推測で埋めず、該当するメンバーと記載を示して、番号を付けて運用者へ確認する |
