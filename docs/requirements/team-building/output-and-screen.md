# 要件定義: 出力と画面

アプリの最終出力はチャット共有用テキストだけとする（利用者の決定、2026-10-18）。Excelは出力しない。
運用でExcelの「時間帯別稼働」「チーム名簿」「別枠」シートが担っていた確認と調整は、画面で行う。

## 1. チャット共有用テキスト

| OUT-009 | 表示のみ | 別枠（参加時間未定）と待機の人数と名前を示す。総力モードでグループがある場合はグループごとにまとめ、移動先（FRM-101）のグループに置く。隊に入らずグループに登録だけする同盟移動協力者（FRM-087）も、「登録のみ（隊なし）」としてグループごとに示す（旧Q-107） |

| OUT-011 | 表示のみ | 警告（FRM-029、FRM-035、FRM-036、FRM-043、FRM-046、FRM-049、FRM-053、FRM-106など）は、チャット共有用テキストと画面の両方に示す（旧Q-008で決定） |
| OUT-015 | 表示のみ | 総力モードでは、隊ごとに次の行を出す（旧Q-107）。見出しは「【第○隊】リーダー: ○○ ／ グループ名（移動先の同盟） ／ 所属人数」とする。別枠に置いたリーダーの隊は「リーダー: 不在」とする（OUT-001）。グループのない総力モードでは、見出しを「【第○隊】リーダー: ○○ ／ 所属人数 ／ ◯最低N(24時以降M) ／ 総力 12,345M」とする。◯最低はOUT-004の形、隊の総力の合計（FRM-085）はA-18の書式とし、総力が未取得のメンバーがいれば総力の後に「(未取得k人)」を添える。隊のファイル（DAT-008）の冒頭に、総力の取得元と取得日をA-18の書式で「総力の取得: 取得元 YYYY-MM-DD」の1行で出す。取得元が複数の場合と0件の場合はA-18による。所属人数は、グループがある見出しと同じく`10人`の形とする。例: `【第1隊】リーダー: ユウ ／ 10人 ／ ◯最低7(24時以降6) ／ 総力 4,567M(未取得1人)`（作成者の仮定A-22）。当てはめない同盟移動の規則と一覧は、formation-rules.mdの11章の前文による（作成者の仮定A-22）。続けて、全時間参加のメンバーを「全時間:」の行に、それ以外のメンバーを参加時間付きで「途中参加・途中抜け:」の行に、それぞれOUT-002の形で並べる。リーダーは参加時間に応じてどちらかの行の先頭に置き、ほかはOUT-013の順とする。上限超えを許した時間帯（FRM-036）と延長保留（FRM-043）などの警告（OUT-011）は「注意:」の行に、応援、遅れて出撃する隊と出撃開始時刻、休止、使わなかった指定（OUT-007）は「注記:」の行に書く。グループがある場合は◯最低（OUT-004）を見出しに付けない。VC可能人数、◆の人数、時間帯ごとの出撃人数は出さない（画面のUI-003で確かめる）。OUT-001の見出しの形は、総力モードではこの形に置き換える |
| OUT-016 | 表示のみ | 総力モードでは、同盟移動の一覧を出す。今の同盟と移動先の同盟の組ごとに「今の同盟→移動先の同盟（人数）: 名前」の行を出し、移動しないメンバーは載せない。協力者同盟（ROS-007）と協力者の欄（ROS-004）のメンバーも載せる（今の同盟が移動先と同じ協力者は含めない。作成者の仮定A-28）。FRM-102の例外として個別に指定した移動先（FRM-101(1)）は、名前に`(指定)`を付ける。行は今の同盟を参加者一覧に現れた順（参加者一覧に現れない同盟はその後に`alliance_choices`に現れた順、協力者同盟は最後）、同じ同盟の中は移動先をグループの設定の順に並べ、名前は参加者一覧の出現順とする（作成者の仮定A-18）。同じ行に同じ名前の別人が並ぶ場合は（行の範囲は作成者の仮定A-18）、名前の後に参加者一覧の同盟の略称を括弧で付ける（例: `ハナ(DDD)`。旧Q-121）。参加時間未定のメンバーには`(未)`を付け、見出しに「(未)＝時間未定」と注記する。待機のメンバーには印を付けない（旧Q-107） |
| OUT-017 | 表示のみ | 総力モードでは、グループごとに登録する人の一覧を出す。見出しは「【グループ名（隊の番号の範囲） 登録 N人】」とし、今の同盟ごとに「同盟（人数）: 名前」の行を出す。隊のメンバーのほか、移動先（FRM-101）がそのグループの同盟である待機と参加時間未定のメンバー（`(未)`を付ける）と、同盟移動協力者を含める。Nはこれらすべての人数とし、協力者を含む場合は「（うち協力者k人）」を添える。グループの人数の上限（FRM-082）と比べる人数は、協力者を除いた数である。行と名前の順、同じ名前の別人の書き方はOUT-016と同じとする（旧Q-107、作成者の仮定A-18） |
| OUT-018 | 表示のみ | 総力モードでは、移動先の同盟ごとに、出るメンバーと入るメンバー（協力者を含む。今の同盟が移動先と同じ協力者は含めない。作成者の仮定A-28）の人数と、移動前から移動後への人数と総力の合計とその差（FRM-103、FRM-104）を出す。グループごとの総力の合計と人数（FRM-085。人数はFRM-082の数え方で、協力者を除く）も出す。総力の目標（FRM-104のウ）を持つ同盟には、目標と不足する量（FRM-106）を書く。総力が未取得のメンバー（0として数える。FRM-104）がいれば、同盟ごととグループごとに未取得の人数を添える。数える範囲はA-18による。総力は百万単位に四捨五入して桁区切りで`12,345M`の形、差は符号を付けて書く。見出しには総力の取得元と、使ったデータのうち最も古い取得時刻の日付（記録した時差のまま）を添え、取得元が複数あれば並べる（旧Q-107、作成者の仮定A-18） |
| OUT-012 | 廃止 | 作業中の確認をコードブロックで示し、最終まとめをファイルで出力する規則は採用しない。前半は対話の手順でありアプリの要件ではない。後半は、最終出力をチャット共有用テキストだけとする決定（本書の冒頭）により置き換える |

## 2. 時間帯別稼働の画面

Excelの「時間帯別稼働」シートが示していた情報を画面で確認し、隊の調整を画面上で行えるようにする。
画面の実装は#16（チーム編成結果）と#15（チーム編成の実行）で行い、`$apple-design`の基準を適用する。
画面はアプリケーションのユースケースを呼び出し、編成ルールや警告の判定を画面へ複製しない。

| ID | 分類 | 要件 |
|---|---|---|
| UI-001 | 表示のみ | 時間帯ごとに、全体の出撃人数、8〜上限（隊ごとの上書きを含む）の人数で組める隊の数、隊ごとの出撃人数の内訳を示す |
| UI-002 | 表示のみ | 時間帯ごとに抜けるメンバーの人数を示す |
| UI-003 | 表示のみ | 隊ごとに、所属人数、時間帯ごとの出撃人数と平均G、VC可能人数、◯最低、◆の人数、上位隊の条件を示す。総力モードでは隊の総力の合計（FRM-085）も示す |
| UI-004 | 表示のみ | 隊の名簿を、時間帯ごとの出撃（○）と応援が分かる表で示す。リーダーと、リーダー不在の時間帯（FRM-002）を区別する。別枠に置いたリーダーの隊は「リーダー不在」と示す。休止した時間帯と、遅れて出撃する隊の出撃開始時刻を示す（FRM-048） |
| UI-005 | 表示のみ | 出撃8人未満の時間帯、◆のいない時間帯、上限超えなどの警告を、色だけに頼らず文言とアイコンで区別する |
| UI-006 | 運用操作 | メンバーを別の隊へ移動できる。移動する前に、影響する時間帯の出撃人数と警告の変化を、アプリケーションのユースケースで計算して示す |
| UI-007 | 運用操作 | 隊のFIX、メンバーのセット、隊数を減らす選択（FRM-005）、下限未満の明示的な許容（FRM-046。許したときの人数を示して指定に含める）を画面で指定できる |
| UI-008 | 運用操作 | 遅れて出撃する隊、出撃開始時刻、応援先（FRM-041、FRM-042）を画面で選べる。応援先を決める必要がある場合は、出力の前にダイアログで問い合わせ、選ぶまで出力しない（旧Q-033で決定） |
| UI-009 | 必須条件 | 画面で変更した編成は、Validatorで独立に再検証してから出力する。画面で変えた運用者の指定も、CLIの回答と同じ確かめ方（FRM-047、FRM-090）でアプリケーションが受け入れてから、Validatorへ渡す。必須条件の違反がある間はテキストを出力しない。運用者が明示した例外（FRM-036、FRM-046）は警告として扱う |
| UI-010 | 運用操作 | 変更前の編成と比べた差分（移動、リーダーの変更、欠落）を示す |
| UI-011 | 表示のみ | 時間帯ごとの出撃（○）は参加時間から計算し、画面で直接編集しない（旧Q-025で決定）。参加時間を直すと出撃を計算し直す |
| UI-012 | 表示のみ | 別枠と待機を、隊とは別の一覧で示す |
| UI-013 | 表示のみ | 通常モードでも、編成の後に画面で隊を選んでグループを作れる。このグループはFRM-004のグループと同じもので、編成と必須条件（FRM-081〜FRM-086）に影響しない（旧Q-054で決定）。「治療時間を計算」ボタンを押すと、グループ別の◯最低の合計と治療時間の目安をOUT-005の形で、アプリケーションのユースケースで計算し、画面に示す（旧Q-041で決定） |
