# Hypothesisで必須条件の性質テストを導入する

## 利用者の依頼

Issue #45: Hypothesisを開発依存へ加え、ValidatorとOptimizerの必須条件を性質テストで検証する

## 実装結果

決定的なProfile、必須条件を満たす編成の生成戦略、Validatorの変異テスト12件、Optimizerの性質テスト5件、ADR 0025を追加した

## 重要な判断

- Profileをtests/conftest.pyで一括適用し、derandomize、database=None、deadline=Noneを固定する
- Validatorは有効な編成へ必須条件を1つだけ破る変更を加え、期待コードだけが出ることを検証して見逃しと誤検出を両方検出する
- A=BとB=Cの同値、境界からずれた参加時刻を生成し、Validatorを一時的に壊す確認で6種類の退行をすべて検出できることを確かめた
- .hypothesis/constants/は定数抽出のキャッシュで、読み込み済みモジュールにより生成が変わり得るため、合否は全体実行で判断する
- AIレビュー（PR #46）のShould 2件に対応した。HypothesisはCI上で同じ値の`ci` Profileを自動で読み込むため、Profileの値だけを見る検査はCIで空振りする。Profile名を検査し、親に`default` Profileを指定した
- 有効な編成の受理テストは、警告を部分集合で比べていたため警告の消失を見逃していた。配置から期待する（コード、チーム、時間帯）を数えて一致を検証する
- Niceは5件に対応した。必須条件エラーを（コード、チーム、時間帯）で比べる、生成戦略の前提をmaster_assumption_errors()へまとめ人数上限はチームマスタから読む、Optimizerの待機参加者を確かめる、テストごとの決定性の上書きをASTで検出する、同じ入力になる条件をDEVELOPMENT.mdへ書く
- A〜Cの時間変化の生成は、8人固定と戦力関係を時間帯ごとに保つ生成が大きくなるため見送り、ADR 0025へ対象外と明記した
- 利用者の判断により、集結主が途中で離脱した時間帯も「到着待ち」の警告とする。docs/architecture.mdへ明記した

## 検証

- python tools/check.py: 129 passed、すべての品質チェックに成功
- 性質テストを2回実行: Hypothesisの統計が一致
- CI=trueで実行: Profileの検査が成功（レビューで、`ci` Profileによる空振りと判明し修正）
- PR #46のCI: Windows、Linux、Python 3.11、3.12の全8ジョブが成功
- レビュー対応後のpython tools/check.py: 130 passed
- conftestのProfile読み込みを外す（CI=true）、8人未満の警告を消す、到着待ちの警告を消す: いずれも対象テストが失敗することを確認
- Nice対応後のpython tools/check.py: 133 passed
- VC違反のチームを誤る、未配置の時間帯を落とす、Dの人数幅をなくす、Optimizerが待機参加者を落とす: いずれも対象テストが失敗することを確認
