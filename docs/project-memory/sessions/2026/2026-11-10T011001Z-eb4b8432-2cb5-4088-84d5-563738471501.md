# 実装Issue 2のPR (a): 所属固定のモデル

## 利用者の依頼

引き継ぎ資料に従い、要件定義書の分割案の2（所属固定のモデル）を実装する。利用者の決定: Issue 1より先に進める、リーダー一覧はsettings.jsonから読む、2〜3件のPRに分ける

## 実装結果

DynamicTeamPlanを所属固定のTeamPlanへ置き換え、リーダー一覧から隊を作るMembershipOptimizer、TeamPlanValidator、Markdown出力、settings.jsonのRepository、チームマスタschema_version 2、Optimizerの結果の3分類、延長境界時刻より前の休止で理由を示して止める扱いを実装した。-kvk-changeで初回と再レビュー3回を経て承認候補（Must・Shouldなし）

## 重要な判断

- ADR 0034: 上位隊3隊×8人、出撃人数の下限8人、延長境界時刻24:00、30分単位をドメインの定数にした。戦力関係は分割案の3まで維持する現行の規則
- 上位隊のリーダー以外の常時稼働（FRM-020〜FRM-022）を、所属固定で8人を保つため分割案の3から前倒しで入れた
- （作成者の仮定）暫定の目的関数: 休止、8人に足りない人数の2乗の和、待機、上位隊の戦力（3:2:1）の辞書式。FRM-031の数はFRM-039と組で分割案の3に入れる
- （作成者の仮定）A-37 リーダー3人未満は入力のエラー、A-38 第4隊以降のリーダー不在は警告（休止と重ねない）、A-39 24:00以降の休止は警告、A-40 戦闘時間の上書きは分割案の1でsettings.jsonから読み、それまでは--team-masterで差し替える
- 運用者の指定のエラーは個人名でなくリーダー一覧の位置で示す（ADR 0026）。DAT-007の未実装のキーは黙って無視せず読み込みエラー
