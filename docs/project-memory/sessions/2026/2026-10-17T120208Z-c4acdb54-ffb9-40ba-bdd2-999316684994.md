# CP-SATテストの決定化と時間切れエラーの区別

## 利用者の依頼

CIのWindowsでまれに失敗する最適化テストを診断し、テストを決定的にし、時間切れと解なしを区別するエラーにする

## 実装結果

原因は5秒の実時間制限と8 worker並列探索で、混んだRunnerではSolverがUNKNOWN（時間切れ）を返していた。テストを1 worker・決定的時間1.0へ変更し、InfeasibleRosterErrorとOptimizationTimeoutErrorを追加した

## 重要な判断

- KvKRulesへ任意のmaximum_deterministic_timeを追加し、既定の運用動作（30秒・8 worker）は変えない（ADR 0019）
- 時間切れと解なしはOptimizationErrorの派生とし、CLIの捕捉と終了コード2を維持する
- worktreeではeditable installがmain側のsrcを読むため、tools/preview_output.pyはPYTHONPATH=srcを付けて実行した

## 検証

- 1コアへ6本の負荷: 旧設定（5秒・8 worker）は3/3が時間切れ、新設定の元の失敗3件は成功
- python tools/check.py: 88 passed、全チェック成功
- python tools/preview_output.py: 必須条件OK。--seconds 0.1で新しい時間切れメッセージと終了コード2を確認

## 未完了事項

- 既定設定（30秒・8 worker）では実行ごとに警告件数が24〜42件と揺れる。既存の挙動で今回は未対応
- CLIに制限時間のOptionはない
- コミットとPull Requestは未作成
