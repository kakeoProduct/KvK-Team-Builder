# devとmainに分けるブランチ運用を導入する

## 利用者の依頼

ブランチ運用を、統合用のdevとリリース用のmainに分ける標準的な運用にしたい

## 実装結果

ADR 0027を追加し、AGENTS.md、DEVELOPMENT.md、README.md、CLAUDE.md、create-github-prとimplementのSkill、構造テストをdevとmainの運用へそろえた。origin/mainからdevを作ってpushした

## 重要な判断

- 作業branchはorigin/devから--no-trackで作り、devへPull Requestで取り込む。mainへはdevからのリリースPull Requestだけをmerge commitで取り込む（利用者の回答）
- 緊急の修正もdevを経由する（利用者の回答）
- （作成者の仮定）dev以外からmainへのPull Requestと、mainをheadにしたPull Requestは、利用者が指定しても作らない
- （作成者の仮定）品質ゲートとレビューをリリースPull Requestにも適用し、リリースのレビューは毎回初回として扱う
- （作成者の仮定）保護規則は承認数0、CIの4 jobを必須、bypass禁止。Require branches to be up to dateとRequire linear historyは有効にしない。merge commitのメッセージはPull Requestのタイトル
- （作成者の仮定）GitHub Pagesの公開元はmainのままとする

## 検証
