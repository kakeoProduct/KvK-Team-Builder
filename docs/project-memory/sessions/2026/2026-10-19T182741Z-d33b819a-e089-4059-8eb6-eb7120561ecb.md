# 公開に備えて実在の名前とゲーム名を伏せる

## 利用者の依頼

CIを無料で使うため、Repositoryを公開できるようにする。実在の名前、同盟名、役割、運用メモ、ゲーム名とイベント名を伏せ、本物のチームマスタをGit管理外から読めるようにする

## 実装結果

集結主、代理集結主、同盟名、Webツールの初期値の名前を架空にし、同梱のteam_master.jsonの役割と運用メモを仮の表記にした。パッケージをkvk_team、配布名とCLI名をkvk-team-builderへ改名し、ゲーム名とイベント名を全追跡ファイルから除いた。CLIへ--team-masterを追加し、マスタの読み込みで型、欠落、未知の項目、時刻の形式を場所付きで検査する。伏せる語の規則をAGENTSに置き、Skill、テンプレート、Review Agentから参照した。ADR 0026を追加

## 重要な判断

- 新しい公開RepositoryはKvK-Team-Builder。同じアカウントの下に作る（作成者の仮定）
- web/のCSSクラスと保存キーの接頭辞ksは残す（作成者の仮定）
- KvKは一般的な用語のため伏せない（利用者が選択）
- pushの前の検査は伏せる語と同梱マスタの検査に限り、品質ゲート全体はReadyの条件に留める
- 途中のコミットの機械検査は見送り。公開後の最初のPull RequestでScriptを加える（利用者が選択、レビューのS28）
- 過去のADRと共有記憶の伏せる語と識別子の表記を書き換えた。ADRの運用規則4と、共有記憶の追記型の規則の例外とした

## 検証

- python tools/check.py: 187件成功
- python tools/preview_output.py: 必須条件OK、警告22件（CP-SATの時間制限で件数は揺れる）
- review-kvk-change: 11回。11回目でS29とS30の解消を確かめ、Must、Shouldなし。S28は見送り（途中のコミットの機械検査）

## 未完了事項

- コミット、Pull Request作成、mainへの取り込みは未実施（利用者の明示が必要）
- 新しい公開Repositoryの作成、git archive mainでの投入、新Repositoryでのpagesの有効化、旧RepositoryのPagesの停止とアーカイブ、GH_TOKENの作り直し
- 途中のコミットを検査するScriptの追加（見送りS28）
- 手元の環境で旧配布物をpip uninstallしてから入れ直す
